## 1. 적용 기준과 구현 범위

### 1.1 명세 작성 기준

- 본문의 `FR`은 기능 요구사항, `AC`는 기능 확인 시나리오의 식별자이다.
- 제4장의 기능은 이번 프로젝트의 구현 대상으로 작성하되, **시연 제외**로 표시한 항목은 식별자와 제외 근거만 유지한다. 특히 **사례 기반 기사 매칭, 동선 연계 할인 예약, 고장 경과 분석 및 사전 인계**는 모두 필수 구현 범위이다.
- **선택 반영:** 사용자는 일반·긴급 여부와 관계없이 기사에게 직접 연락하여 상담·방문·수리를 협의할 수 있다. 사진 접수, AI 문답·분석, 앱 상담·견적·예약·인계는 필요할 때 이용하는 보조 기능이다. 필수 구현은 모든 사용자가 해당 절차를 반드시 거친다는 뜻이 아니다. 직접 연락에는 이 절차들의 완료를 요구하지 않으며, 앱 기능을 선택한 경우에만 해당 저장·권한·예약 규칙을 적용한다.
- 각 기능 묶음의 **근거**는 기준 문서의 절 번호를 가리킨다. 시장 규모, 경쟁 서비스의 기능, 수익 예시는 서비스 요구사항으로 옮기지 않는다.
- 원문 기능을 실제 동작으로 연결하기 위해 도출한 처리 규칙에는 **명세화**를 표시한다. 상태 명칭과 예외 처리 등 원문에 직접 명시되지 않은 내용을 구분하기 위한 표기이다.
- 사용자가 선택한 구체적 정책과 기획서 대비 시연 범위 조정은 **선택 반영**으로 구분한다. 제1.4절·제9장의 선택은 기획서 원문을 수정하거나 원문이 해당 세부 정책까지 확정했다는 뜻이 아니다.
- **의도 정정**은 기존 문서가 사용자의 의도를 잘못 표현한 부분을 바로잡는 표기이다. 앱의 사진·Markdown 보고서와 사진 포함 PDF 추출, 기사 사진의 본인 프로필 저장에 적용하며 새로운 범위 축소로 설명하지 않는다. Markdown 본문은 앱과 PDF에서 읽기 좋게 렌더링하여 표시한다.
- **재검토 기준:** 지각 시작 관련 사항은 기존 일정·실제 작업 규칙으로 다루며 같은 보완을 다시 제안하지 않는다. 확정 예약 조건 버전의 추가 세분화도 이번 검토에서 요구하지 않는다. 사용자 확인으로 정리한 사항을 미해결 과제로 되살리거나 기획 위반으로 재분류하지 않는다.
- 기능의 입력·출력·예외·확인 기준을 작성한다. 담당자 배정·마감·프로젝트 관리, 프론트엔드 구현과 배포 설계는 다루지 않는다. 미정인 검수 수치를 합격으로 처리하지 않는다.

### 1.2 이번 프로젝트의 구현 범위

| 구분 | 포함 기능 및 범위 |
| --- | --- |
| 기본 접수·분석 | 사진·증상 접수, 추가 기록, AI 문답, 증상 요약·분야 후보, 사용자 확인·수정, 독립적으로 처리할 작업 항목 관리 |
| 해결 경로 | 검증 자료에 근거한 자가 해결 안내, 제조사 공식 AS 안내·결과 기록, 수리기사 연결, AI 처리와 독립적인 긴급 안내 |
| 기사 연결·예약 | 공개 업무 연락수단을 통한 직접 연락, 선택적인 작업 항목별 기사 탐색·상담·견적·예약, 같은 요청 안의 다른 기사 방문 시간 중복 확인, 예약 조회·변경·취소 |
| 핵심 기능 1 | 해결 사례 검색, 담당 기사 연결, 추천 근거 제공, 지역·분야·시간 조건 반영. 시연은 모의·재현자료로 수행한다. |
| 핵심 기능 2 | 고정 시각 또는 유연한 방문 기간 등록, 인근 일정·빈 시간 연계, 기사 자율 할인 제안 |
| 핵심 기능 3 | 날짜별 기록, 사진 변화 분석, 사진과 Markdown 본문을 함께 보는 보고서, 사용자 검토, 사진 포함 PDF 추출 및 방문 전 인계 |
| 기사 업무 | 작업 항목별 상담 관계 수락·거절, 외부 연락으로 추가 확인, 일정 관리, 방문 준비사항, 방문 불가 취소, 조기 시작 동의·작업 시작·완료·중단·진행 중 변경 합의, 마이페이지의 과거 작업 사진·사례 등록 |
| 계정·권한 | 사전 발급 테스트 계정 로그인, 사용자·기사 역할 전환, 기사별 프로필·일정 분리, 자기 요청 참여 차단 |
| 정보 관리 | 선택한 상대에게 필요한 전달본 제공, 수동 가림·자료 제외·메타데이터 제거, 진행 중 본인 사진 삭제, 관계별 공개 범위와 요청 전체 삭제 통제 |
| 프로젝트 검증 | 기준 사례·모의 일정·평가 사진을 이용한 AI 에이전트 모의평가 및 규칙 검사 |

**선택 반영:** 사진 변화 분석 대상은 **벽지 물자국**이다. 사례 매칭과 할인 예약은 준비한 모의 사례·재현 사진, 기사 프로필, 모의 일정으로 작동 여부를 검증하며, 이를 실제 작업 실적으로 표시하지 않는다.

| 항목 | 구분 이유 |
| --- | --- |
| 플랫폼 내 실결제, 수수료 부과·정산 | 기획서 제7.1절에서 사업화 단계의 구체화 대상으로 분리한다. |
| 부품·도구 커머스, 폐기·교체 제휴, B2B 외부 시스템 연동 | 기획서 제7.1절의 향후 확장 범위이다. |
| 업체 구독·광고, 유료 노출, 자격 인증 배지 | 기획서 제8장의 사업화 모델이며 이번 구현 기능으로 확정되어 있지 않다. |
| 영상·음성·오류 코드 입력, 예방 관리, 이사 관리, B2B 시설관리 | 기획서 제9장의 확장 방향이다. |
| 리뷰·평점, 관리자 콘솔, 푸시·문자 알림 | 경쟁 서비스 설명과 별개로 고쳐야집의 이번 구현 요구사항에 명시되지 않았다. |
| 별도 활용 동의, 실제 접수자료의 공개 포트폴리오·별도 AI 활용 전환 | **선택 반영:** 기획서 제7.4절의 원문 요구와 구분하여 이번 시연에서는 제외한다. FR-INF-03은 제외 식별자로 남기고, FR-WRK-03은 실제 접수자료 전환 차단만 검수한다. 준비된 모의·재현자료의 사례 관리·평가는 유지한다. |
| 사용자·기사 간 앱 내 채팅·대화 저장·통화 연결, 보고서 외부 공유 링크, Markdown 파일 다운로드 | **선택 반영:** 사용자·기사 간 앱 내 채팅과 비동기 질문·답변 대화 저장은 이번 구현에서 제외하며, 사용자·기사 간 채팅은 추후 구현 예정이다. 상담은 기사가 공개한 전화번호·외부 연락수단으로 진행한다. 앱은 상대 선택·수락, 확인 자료 전달, 견적·예약·방문 준비사항을 관리하며 외부 대화 내용이나 연결 성공을 수집하지 않는다. 사용자와 AI의 문답은 유지한다. 보고서는 앱에서 사진·Markdown 본문을 표시하고 사진 포함 PDF로 추출하며, 외부 공유 링크와 .md 파일 다운로드는 제공하지 않는다. |
| 공개 회원가입·업체 다중 계정 관리 | **선택 반영:** 사전 발급한 테스트 계정과 기사별 독립 프로필·일정으로 시연한다. |
| 프론트엔드 화면 구현·배포 설계 | 이번 문서 개정의 작업 범위에서 제외한다. |

### 1.4 선택한 서비스 범위와 시연 자료

다음은 기획서 원문과 구분되는 **선택 반영** 사항이다. 상세 동작은 제4장·제6장, 확인 기준은 제7장·제8장에 연결한다.

| 항목 | 적용 내용 |
| --- | --- |
| 서비스 지역·분야 | 서울 전역의 수도·배관, 문·창호, 벽면·도배, 조명·전기설비, 생활가전 5개 분야에서 기사 탐색·예약을 지원한다. 세탁기·에어컨은 생활가전 시연 자료의 예시이며 지원 제품을 이 둘로 제한하지 않는다. 시연 사진·사례가 없는 제품도 기사 분야·지역·일정 등 조건에 맞으면 추천·견적·예약을 제공한다. |
| 시연 자료 | 모의 사례·재현 사진 중심. 서울 전역의 동 단위 대표 위치, 동 내부·동 간 고정 모의 이동시간표, 기사별 출발·복귀 위치를 사용한다. 지원 동 목록과 자료 버전을 연결하고 전역의 자료 범위를 검수한다. 실제 도로 이동시간을 보장하지 않는다. |
| 직접 연락·긴급 문의 | 기사 표시명·분야·활동 지역·기사가 공개한 업무 연락수단으로 연락한다. 일반·긴급 모두 접수·AI·일정 입력·상담 수락·견적·예약 없이 이용할 수 있다. 긴급 문의도 사례 점수·빈 일정·이동표 검사를 연락의 선행 조건으로 두지 않으며 실제 방문 가능 여부·시각·금액은 직접 협의한다. |
| 지원 범위 밖 접수 | 접수·기록은 허용한다. 서울 밖·미지원 분야의 조건 충족 추천·예약과 미지원 변화 분석은 제공하지 않는다. 시연 자료·연관 사례·공식 AS 자료의 부재는 각각 표시하며 기사 추천·예약의 지원 제외 사유로 삼지 않는다. 공개 기사 연락수단·등록 공식 안내는 유지하고, 서울의 이동자료 누락은 보완 대상으로 처리한다. |
| 계정·사진·문답 | 테스트 계정의 역할 전환, 사용자 요청 사진의 JPEG·PNG·파일당 10MB·한 번에 5장·요청당 30장, 촬영일 사용자 확인, 복수 분야 탐색·추가 문답 최대 5회를 적용한다. 기사 업로드 사진은 본인 프로필의 포트폴리오에 저장하며 요청 사진과 한도를 공유하지 않는다. |
| 예약·실제 작업 | 앱 예약을 이용하면 작업 항목별 활성 예약 하나를 허용한다. 같은 요청의 다른 기사 방문 시간 중복은 사용자 확인 후 허용하고 같은 기사 충돌은 모든 요청에서 차단한다. 사용자 동의로 조기 시작하며, 진행 중 범위·금액·예상 종료 변경은 양측 합의와 충돌 해소 후 반영한다. 직접 연락만으로 앱 예약·점유·작업 완료가 생성되지는 않는다. |
| 기록·공유 | 정정은 수정 이력 없이 덮어쓰고 최종 수정일을 갱신한다. 자료 변경 시 갱신 필요만 표시하며 비용이 발생하는 AI 재분석·요약 재생성은 사용자가 요청할 때만 실행한다. 직접 요약을 수정·확인할 수도 있다. 공개 범위·가림만 바뀌면 전달본·PDF만 다시 확인한다. 앱에서는 사진·촬영일·Markdown 본문을 보고 확인한 범위를 PDF로 추출한다. |
| 보관·삭제 | 서비스 자료는 팀이 삭제할 때까지 보관하되 본인 개별 삭제 API를 제공한다. 진행 중에도 본인 사진은 삭제할 수 있다. 요청 전체와 사진 외 기록은 활성 관계 제한을 유지한다. |
| 평가·완료 | 별도 비식별 평가 자료·실행 기록은 최종 평가 검증까지 보존한다. 사진은 기존 전체 평균으로 판정하며 유형별 추가 합격선을 두지 않는다. 필요한 AI 결과의 무출력은 실패이고, 일반 API 성능은 기능·AI 품질과 별도 후속 검수이다. |

FastAPI·Python, PostgreSQL, OpenAI SDK는 **사용 예정 기술이라는 참고 정보**이다. 기술 확정이나 특정 API·저장 구조·프론트엔드·배포 설계의 요구사항으로 해석하지 않는다.

## 3. 주요 이용 흐름

### 3.1 사용자 흐름

**직접 연락 경로:** 일반·긴급 요청 모두 공개 기사 목록·프로필의 업무 연락수단으로 바로 문의할 수 있다. 로그인·사진 접수·AI 결과·방문 가능 시간 입력을 요구하지 않는다. 분야·지역 필터는 직접 선택할 수 있고 미선택이면 공개 목록에서 확인한다. 기사가 등록한 분야·활동 지역을 보고 문의하되, 실제 대응 가능 여부와 방문 시각·금액은 연락으로 확인한다. 이미 접수·앱 상담·예약 중이어도 직접 연락할 수 있다.

아래는 사용자가 보조 기능을 선택할 때의 이용 흐름이다. 연락만으로 진행한 결과를 앱에 남기거나 앱 예약으로 전환하는 것은 선택이다.

1. 테스트 계정으로 로그인하고 사용자 역할에서 사진·증상을 접수한다. 지원 여부와 미확인 제품 정보는 별도로 표시한다.
2. AI를 이용하면 최대 5회 추가 문답에 답하거나 현재 정보로 진행하여 요약·복수 분야를 확인한다. AI를 선택하지 않으면 사용자가 분야·요약을 직접 입력·확인하고 기사 탐색·견적·예약으로 진행한다. AI 미선택은 실패와 구분하며 분석을 먼저 실행할 필요가 없다.
3. 독립적으로 처리할 작업 항목을 확인하고 항목별로 자가 해결, 제조사 AS, 기사 연결 경로를 선택한다. 복수 분야 후보만으로 작업을 자동 분리하지 않는다.
4. 사례·일정 조건에 맞는 추천을 이용하려면 요청의 작업 지역과 항목별 방문 가능 조건을 등록한다. 유사 사례·추천 근거를 확인하며, 동선 제안 탐색을 선택한 경우에는 최소 작업 정보를 보고 상담 참여 의사를 표시한 기사도 비교하여 상담 상대를 선택한다. 공개 연락수단으로 직접 문의할 때에는 추천용 입력을 요구하지 않는다.
5. 기사가 공개한 연락수단으로 직접 연락해 추가 정보를 확인한다. 필요한 사진·설명은 사용자가 접수 자료에 보완하고, 앱에서 기사 제안의 분야·범위·수량·방문 시각·금액을 비교한다. 사용자·기사 간 대화는 앱에 저장하지 않는다.
6. 상세 주소·방문 연락처를 입력·확인하고 항목별로 최신 유효 제안을 선택한다. 다른 기사 방문 시간이 겹치면 해당 중복을 확인한 뒤 예약을 확정한다. 각 항목의 경쟁 상담만 종료하며 상세 방문 정보는 확정 전까지 공개하지 않는다.
7. 최신 경과와 해당 작업의 인계서를 확인하고 확정 기사에게 필요한 정보를 전달한다. 앱의 사진·Markdown 보고서를 검토하고 공유할 범위는 사진 포함 PDF로 추출할 수 있다.
8. 필요한 경우 조기 시작에 동의하고 실제 시작·완료 기록을 확인한다. 시작 후 범위·금액·예상 종료 변경안을 검토할 수 있으며 양측 합의와 충돌 해소 전에는 추가·변경 작업을 진행하지 않는다. 중단이 필요하면 중단을 요청하여 기사 확인과 수행 기록을 조회한다.
9. 각 예약의 취소·완료·중단과 함께 해당 상담의 종료를 확인한다. 다른 작업은 계속 진행할 수 있으며, 모든 활성 관계가 정리되면 해결 또는 더 진행하지 않음을 확인하여 요청 전체를 종료한다.

자가 해결로 해당 작업이 해결되면 결과를 기록한다. 해결되지 않으면 같은 요청·작업 항목의 사진·문답·조치 기록을 유지한 채 기사 연결로 진행한다. 제조사 AS 결과도 항목별로 기록하고 미해결이면 경로를 다시 선택한다. 외부 결과는 사용자 진술로 구분하며 다른 작업의 활성 관계를 자동 종료하지 않는다. 요청 전체 종료는 사용자의 최종 확인을 거친다.

과거 사진이 없어도 최초 사진 한 장과 문답으로 상담·예약 및 인계서 생성을 진행할 수 있다. 사용자가 긴급성을 표시하거나 사전 정의된 긴급 입력에 해당하면 AI 분석·분류·요약 확인의 완료를 기다리지 않고 검증된 긴급 안내를 우선 제공한다. 적합 기사가 없어도 안내를 유지하며 할인 대기나 반복 분석을 선행 조건으로 두지 않는다.

직접 연락으로 해결한 결과는 기존 요청이 있으면 해당 항목에 사용자 진술로 남길 수 있다. 앱의 활성 상담·예약을 자동 종료하거나 외부 합의를 앱 예약으로 간주하지 않으며, 요청 전체를 종료할 때에는 기존 활성 관계를 해당 절차로 정리한다.

### 3.2 기사 흐름

기사는 공개 업무 연락수단을 등록하고 직접 들어온 문의에 응답하여 필요한 정보·방문·금액을 협의할 수 있다. 앱 상담 수락이나 견적 발행은 연락의 선행 조건이 아니다. 아래 절차는 앱의 상담·예약·작업 관리 기능을 함께 이용하는 경우에 적용한다.

1. 테스트 계정의 기사 역할에서 마이페이지에 공개 연락처·전문 분야·활동 지역·독립 일정을 등록하고, 그동안 수행한 작업 사진을 본인 포트폴리오에 업로드한다. 사례 시연에는 준비된 모의·재현자료를 사용한다. 자기 계정의 요청에는 기사로 참여할 수 없다.
2. 동선 추천에서는 작업 항목의 최소 정보만 확인하고 상담 참여 의사를 표시한다. 사용자가 해당 항목의 상담 상대로 선택한 후에 허용된 사진·요약을 열람하고 상담 관계를 수락·거절한다. 추가 정보는 전화·외부 연락으로 확인한다.
3. 작업 분야·범위·수량과 예상 소요 시간을 확인하고, 세부 비용, 방문 시작·예상 종료 시각 및 필요한 경우 할인 조건을 제안한다.
4. 사용자 선택으로 확정된 예약을 확인하고 인계서를 검토한다.
5. 추가 확인은 외부 연락으로 진행하고, 준비할 장비·부품·점검 항목은 앱에 방문 준비사항으로 등록한다.
6. 본인의 다른 진행 작업과 이동 조건을 확인한 뒤 실제 시작을 기록한다. 예정 시각 전이면 사용자 동의를 받는다. 추가·변경 작업은 범위·금액·예상 종료를 양측이 확인하고 후속 충돌을 해소한 뒤 수행한다.
7. 완료·중단 시 실제 종료와 수행 내역을 해당 예약에 기록하고 상담을 종료한다. 기사 사진은 본인 마이페이지의 과거 작업 포트폴리오에 등록하며 사용자 요청에는 업로드하지 않는다. 시작 전 방문 불가이면 사유와 함께 예약을 취소한다. 다른 작업의 상태와 접근 권한은 관계별로 유지한다.

## 4. 기능 요구사항

### 4.1 사진·증상 접수 및 요청 기록

**주체:** 사용자, 시스템 · **근거:** 제4.1절, 제5.1절, 제6.3절

| ID | 기능명 | 요구사항 | 확인 기준 |
| --- | --- | --- | --- |
| FR-REQ-01 | 문제 접수 | 사용자는 문제 부위의 사진과 간단한 증상을 하나의 요청으로 등록할 수 있어야 한다. | 최초 사진 한 장과 증상 설명으로 요청을 생성하고 해당 사진·설명을 함께 조회할 수 있다. |
| FR-REQ-02 | 과거·추가 자료 등록 | 사용자는 과거에 촬영한 사진과 이후 촬영한 사진, 추가 설명을 기존 요청에 덧붙일 수 있어야 한다. | 추가 자료가 새 요청으로 분리되지 않고 기존 요청에 연결된다. |
| FR-REQ-03 | 사진 날짜 관리 | 촬영 날짜와 업로드 시각을 구분한다. **선택 반영:** 사진 메타데이터의 촬영일은 후보로만 제시하고 사용자가 확인·입력한 날짜를 경과 날짜로 사용한다. 모르는 날짜는 미확인으로 둔다. | 메타데이터만으로 촬영일이 확정되지 않는다. 확인된 사진은 촬영일순으로, 미확인 사진은 별도 묶음으로 조회하며 업로드일을 촬영일로 대체하지 않는다. |
| FR-REQ-04 | 증상·조치 정보 수집 | 최초 발견 시점, 발생 위치·조건, 반복 여부, 시도한 조치·결과를 입력하거나 문답으로 보완한다. **선택 반영:** 제품 종류·제조사·모델명은 최초 접수에서 각각 모름을 허용하고 공식 AS 안내에 필요한 정보만 이후 보완한다. | 제품 정보가 미확인이어도 접수가 저장되고 상담·인계에 재사용된다. 발견일·촬영일·최종 수정일이 구분되며 모름을 확정 사실로 바꾸지 않는다. |
| FR-REQ-05 | 요청 이력 조회 | 사용자는 요청의 공통 사진·문답·경과와 작업 항목별 상담·예약·외부 AS 및 직접 연락 결과·시작·완료·중단·변경 합의를 조회할 수 있어야 한다. | 작업 항목과 예약의 상태를 요청 전체 종료 상태와 구분한다. 사용자 진술의 외부 결과와 앱 예약의 기사 수행 기록을 구분하며 다른 항목의 이력을 섞지 않는다. |
| FR-REQ-06 | 작업 지역 등록·수정 | **명세화:** 사용자는 사례·일정 조건에 맞는 추천 전에 실제 작업 지역을 시·군·구 및 읍·면·동 수준으로 등록·수정한다. 최초 사진 접수나 자가 해결 안내에 상세 주소 입력을 요구하지 않는다. 공개 기사 목록 조회·직접 연락에는 요청의 지역 등록을 강제하지 않는다. | 작업 지역이 기사 활동 지역 및 동선 조건 검사에 사용된다. 지역 미입력 시 조건 충족 기사로 확정 표시하지 않고 입력을 요청하며, 수정 시 기존 추천·제안의 적합성을 재검사한다. 공개 연락 목록은 조건 충족 추천과 구분한다. |
| FR-REQ-07 | 상세 방문 정보 확인 | **명세화:** 사용자는 앱 예약 확정 전에 상세 주소와 방문 연락처를 입력·확인하고, 저장된 작업 지역과 일치하는지 확인해야 한다. 확정 후 변경은 제6.2절의 변경 절차를 따른다. | 정보가 빠지거나 작업 지역과 불일치하면 보완 후 확정한다. 앱에 저장한 사용자 방문 정보는 입력만으로 상담 기사에게 공개되지 않으며, 예약 확정 후 담당 기사에게 필요한 정보만 제공된다. 기사 공개 연락수단 조회와 외부 연락 중 당사자가 직접 알려주는 정보는 이 입력 절차를 요구하지 않는다. |
| FR-REQ-08 | 지원 범위 판별 | **선택 반영:** 서울 전역의 지원 분야에서 조건에 맞는 기사 추천·앱 예약을 제공한다. 시연 자료·연관 사례의 유무와 서비스 지원 여부를 구분한다. 시연 자료가 없는 제품도 등록 분야·지역으로 기사를 탐색하고 기사 확인 조건으로 견적·예약할 수 있다. | 서울 밖·미지원 분야의 조건 충족 추천·예약과 벽지 물자국 외 변화 분석은 제공하지 않는다. 냉장고 등 시연 자료가 없는 생활가전도 기사 조건이 맞으면 일반 후보 추천·예약을 제공한다. 없는 사례·공식 안내·시간 적합성을 만들어내지 않고 필요한 작업·이동 조건은 확정 전에 보완·검사한다. 공개 연락은 이러한 자료 유무로 막지 않는다. |
| FR-REQ-09 | 요청 사진 입력 제한 | **선택 반영:** 요청 소유 사용자가 업로드하는 사진은 JPEG·PNG만 허용하며 실제 파일 형식·읽기 가능 여부를 검사한다. 파일당 10MB(10,000,000바이트) 이하, 업로드 한 번에 최대 5장, 요청 전체의 저장 사진 합계 최대 30장이다. 모든 항목에서 사용자가 올린 접수·상담 보완·경과·조치 결과 사진을 합산하며 공유 참조만으로 같은 사진을 중복 집계하지 않는다. | 오류·한도 초과 묶음은 저장하지 않고 항목·사유를 반환한다. 경계값은 허용하며 동시 업로드도 총량을 초과하지 않는다. 진행 중에도 FR-INF-07에 따라 본인 사진을 삭제해 한도를 회복할 수 있다. 기사 사진은 본인 프로필에 저장하며 요청 사진으로 업로드하거나 이 한도에 합산하지 않는다. |
| FR-REQ-10 | 작업 항목 관리 | **선택 반영:** 하나의 요청 안에 독립적으로 처리할 작업 부위·종류를 사용자 확인으로 구분한다. 기본 항목 하나로 단일 작업을 진행할 수 있고, 같은 분야도 별도 작업이면 항목을 추가할 수 있다. 각 상담·견적·예약은 항목 하나에 연결한다. | 복수 분야 후보만으로 작업을 자동 생성하지 않는다. 항목별 사실·방문 조건·상태·관련 자료를 구분하며 한 항목의 변경·종료가 다른 항목을 변경하지 않는다. 기사 분야 후보와 사용자가 확정한 작업 단위를 구분한다. |
| FR-REQ-11 | 요청 전체 종료 확인 | **선택 반영:** 사용자는 모든 작업 항목의 활성 상담·예약·작업을 정리한 뒤 해결 또는 더 진행하지 않음을 확인하여 요청 전체를 종료한다. 더 진행하지 않는 미해결 항목은 해결 완료와 구분한다. | 한 항목 완료로 전체 요청을 자동 종료하지 않는다. 활성 관계가 있으면 필요한 정리 절차를 안내하며 자동 취소하지 않는다. 전체 종료와 새 상담·예약이 경합해도 종료 요청에 활성 관계가 생기지 않으며, 종료와 자료 삭제를 구분한다. |

### 4.2 AI 문제 파악 및 사용자 확인

**주체:** 사용자, AI, 시스템 · **근거:** 제4.1절, 제5.1절, 제5.3절

| ID | 기능명 | 요구사항 | 확인 기준 |
| --- | --- | --- | --- |
| FR-AI-01 | 증상 요약·분야 후보 | AI는 사진·설명에서 증상 요약, 관련 수리 분야와 가능한 원인 후보를 제시한다. **선택 반영:** 사용자는 한 작업 항목에 대해 복수 분야로 동시에 탐색할 수 있고, 독립 작업의 분리는 별도로 확인한다. | 원본 증상과 근거, 후보별 분야를 확인한다. 복수 분야를 하나로 강제 축소하거나 대안 분야마다 작업 항목을 자동 생성하지 않는다. 가능한 원인과 현장 확인 원인을 구분한다. |
| FR-AI-02 | 맞춤 추가 문답 | 현재 정보에 부족한 항목을 질문하고 답변을 요청에 저장한다. **선택 반영:** 요청당 추가 문답은 최대 5회이다. 한 회는 질문 1개와 답변 또는 건너뛰기로 세며, 사용자는 언제든 현재 정보로 확인 단계에 진행할 수 있다. | 6번째 질문을 만들지 않으며 재시도·재접속으로 횟수를 초기화하지 않는다. 조기 종료·건너뛰기 시 저장된 답변과 미확인 항목을 표시하고, 필수 예약 정보는 이후 해당 단계에서 보완한다. |
| FR-AI-03 | 정보 성격 구분 | 결과 화면은 사진에서 관찰한 사실, 사용자 설명, AI 추정, 미확인 사항을 명확히 구분해야 한다. | 같은 결과에서 각 정보의 성격을 식별할 수 있고, 추정이 현장 확인 사실로 표시되지 않는다. |
| FR-AI-04 | 분석 결과 확인·수정 | 사용자는 AI 결과를 이용하는 경우 증상 요약과 수리 분야를 확인·수정한 뒤 추천·자료 전달에 사용한다. **명세화:** 견적 전제가 바뀌면 제6.2절의 요청 공통·작업 항목·기사 제안별 범위에 따라 재확인을 요구한다. | 수정이 관련 항목의 검색·상담에 반영된다. 한 항목의 분야 정정으로 무관한 항목의 견적을 무효화하지 않고, 변경 전제를 확인하지 않은 견적은 확정하지 않는다. 일반·긴급 직접 연락과 긴급 안내는 분석·요약 확인을 기다리지 않는다. |
| FR-AI-05 | 위험 신호와 판단 한계 표시 | AI는 가능한 위험 신호를 참고 정보로 제시하고, 사진만으로 원인·안전성·최종 수리비를 단정하지 않아야 한다. | 불확실한 사항과 현장 점검 필요 여부가 표시되며, 원인 후보가 확정 진단처럼 제시되지 않는다. |
| FR-AI-06 | AI 작업 접수·상태·결과 조회 | **선택 반영:** AI 처리를 접수하면 작업 식별자·상태·접수 시각을 반환하고 요청 권한 안에서 상태·결과·오류를 조회할 수 있어야 한다. 전체 처리시간 60초와 최대 1회 자동 재시도는 제6.8절을 따른다. | 대기·처리 중·성공·실패·시간 초과를 구분한다. 조회가 작업을 재실행하지 않으며 제한시간 초과·낡은 입력의 결과를 성공한 최신 확정본으로 전달하지 않는다. |

| --- | --- | --- | --- |
| FR-SOL-01 | 해결 경로 제시·선택 | 접수 결과에 따라 작업 항목별로 자가 해결, 제조사 AS, 기사 연결 중 적합한 경로와 안내를 제공하고 사용자가 선택할 수 있어야 한다. | 기존 접수 자료를 재사용하며 한 항목의 경로 선택으로 다른 항목의 상담·예약을 바꾸지 않는다. |
| FR-SOL-02 | 자가 해결 가이드 | 검증된 자료의 적용 조건·허용 단계·주의·필요 용품·금지·중단 기준을 원문·버전과 함께 제공한다. **선택 반영:** 이 내용은 고정하고 설명 표현만 사용자 상황에 맞춘다. 가이드와 공식 경로는 사전 등록·버전 관리한다. | 적용 불가이면 실행 절차 대신 중단·대체 경로를 안내한다. 조건·순서·주의·중단 의미를 바꾸거나 미등록 절차를 생성하지 않는다. 원문 일치율 95% 이상, 치명 실패 0건을 제8장에 따라 검수한다. |
| FR-SOL-03 | 자가 조치 결과·전환 | 사용자는 시도한 조치·결과를 항목에 기록하고 해결 표시 또는 해당 항목의 기사 연결을 선택한다. 활성 상담·예약이 있다면 해당 절차로 정리하며 자가 해결 표시로 우회 종료하지 않는다. | 전환해도 기존 사진·문답·조치 결과를 유지한다. 다른 항목은 유지하며 요청 전체 종료는 FR-REQ-11의 사용자 확인을 거친다. |
| FR-SOL-04 | 제조사 공식 AS 안내·결과 기록 | 제품 정보에 맞는 사전 확인·등록된 제조사 공식 지원·예약 경로만 제공한다. 필요한 제품 종류·제조사·모델명을 보완 요청하고 확인 가능한 일반 공식 경로는 구분해 제공한다. 사용자는 항목별 외부 해결 결과를 기록하거나 미해결 경로를 다시 선택한다. | 알 수 없는 제조사·모델·URL·연락처를 생성하지 않는다. 경로가 없으면 안내 불가·보완 필요를 표시한다. 외부 결과는 사용자 진술이며 활성 플랫폼 예약을 자동 종료하지 않는다. 기존 자료와 다른 항목을 유지하고 전체 종료는 FR-REQ-11을 따른다. |
| FR-SOL-05 | 긴급 안내·기사 직접 연락 | 누수·단전 등 긴급 요청에는 검증된 대응 안내와 기사 직접 연락 경로를 우선 제공한다. **선택 반영:** 등록 분야·활동 지역·공개 업무 연락수단으로 문의할 기사를 찾으며 AI 처리·사례 점수·일정 등록·이동표·견적·앱 예약을 연락 조건으로 요구하지 않는다. | 비로그인·접수 전·AI 실패에도 안내와 공개 연락수단을 확인한다. 실제 대응·방문 가능 여부는 기사에게 직접 확인하도록 표시한다. 공개 연락 가능한 기사가 없으면 그 사실과 등록된 공식 대안 경로를 안내하며, 연락처·응답·즉시 방문 가능성을 만들어내지 않는다. |

### 4.4 기사 프로필·일정·수리 사례 관리

**주체:** 기사, 시스템 · **근거:** 제4.2절, 제5.2절, 제6.1절, 제6.2절, 제7.3절

| ID | 기능명 | 요구사항 | 확인 기준 |
| --- | --- | --- | --- |
| FR-PRO-01 | 기사 프로필 관리 | 기사는 표시명, 전문 수리 분야, 주요 활동 지역, 대표 포트폴리오와 공개용 업무 전화번호·외부 연락수단을 등록·수정할 수 있어야 한다. **선택 반영:** 공개 연락수단은 기사 본인이 공개하도록 등록한 값만 사용하며 프로필·사용자 역할 정보는 기사별로 구분한다. | 공개 표시명·분야·활동 지역·업무 연락수단은 직접 연락 목록에 반영한다. 연락수단이 없거나 공개를 중단하면 직접 연락 가능으로 표시하지 않는다. 시연에는 사용 가능한 공개 업무 연락수단을 준비하며 다른 계정의 개인정보를 대신 사용하지 않는다. 한 기사의 수정이 다른 기사 자원에 반영되지 않는다. |
| FR-PRO-02 | 방문 가능 일정 관리 | 기사는 방문 가능 시간과 기존 방문 일정을 관리한다. 서울 동 단위 작업 위치·예상 소요 시간과 같은 기준의 출발·복귀·이동자료를 사용한다. | 등록 일정으로 가능·점유 구간을 구분한다. 서로 다른 요청·작업 항목도 같은 기사 일정에서는 함께 검사한다. |
| FR-PRO-03 | 마이페이지 작업 사진·수리 사례 관리 | 기사는 본인 마이페이지의 포트폴리오에 그동안 수행한 작업 사진을 업로드할 수 있다. 사례에는 최초 증상, 확인된 원인, 작업 내용, 부품, 전후 사진을 구분하여 등록·수정한다. 기사 사진은 본인 프로필에 속하며 사용자 요청·상담·예약에 업로드하지 않는다. 이번 시연의 사례는 준비된 모의·재현자료를 사용하고 실제 접수자료를 공개 사례로 전환하지 않는다. | 본인이 올린 작업 사진·사례를 마이페이지에서 확인하고 수정한 사례가 검색·추천에 반영된다. 기사 사진은 요청 사진 수·경과 기록과 분리하며 다른 기사 프로필을 수정할 수 없다. 출처·모의 라벨·미확인 원인과 식별 정보 제거를 확인하고 완료 기록을 자동으로 사례로 만들지 않는다. |
| FR-PRO-04 | 사례 출처·유형 관리 | 사례에는 출처와 담당 기사를 연결하고 실제 사례인지 시연용 모의 사례인지 구분해야 한다. | 검색 결과와 사례 상세에서 출처·실제/모의 구분을 확인할 수 있고, 모의 사례가 실제 실적으로 표시되지 않는다. |
| FR-PRO-05 | 확정 예약을 보호하는 일정 변경 | **명세화:** 기존 방문 일정의 추가·수정과 방문 가능 시간 변경 시에도 확정 예약의 작업·이동 시간을 포함한 충돌을 검사해야 한다. 충돌하는 변경은 저장하지 않고 해당 예약의 변경·취소 절차를 안내한다. | 확정 후 외부 일정을 추가하거나 가능 시간을 줄여도 확정 예약이 조용히 덮어써지거나 충돌 상태로 남지 않는다. 충돌을 해소한 변경만 반영되며, 변경과 신규 예약이 동시에 처리되어도 같은 규칙을 지킨다. |

### 4.5 실제 해결 사례 기반 기사 매칭

**주체:** 사용자, AI, 시스템 · **근거:** 제5.1절, 제5.3절, 제6.1절, 제7.1절

| ID | 기능명 | 요구사항 | 확인 기준 |
| --- | --- | --- | --- |
| FR-MAT-01 | 증상 연관 사례 검색 | 사용자가 확인한 복수 분야와 증상으로 사례를 함께 검색한다. **선택 반영:** 사례 관련성 1~5점 중 3점 이상만 연관 사례로 채택하고, 기사별 상위 3개 평균(1~2개면 해당 평균)으로 상위 기사 5명을 선정한다. 제6.5절을 따른다. | 사례 점수·근거·집계 대상·기사 평균을 재현할 수 있다. 같은 사례·기사는 분야가 겹쳐도 중복 집계·표시하지 않고, 적합 추천이 5명 미만이면 실제 수만 제공한다. |
| FR-MAT-02 | 사례·담당 기사 연결 | 추천 사례를 수행한 기사와 해당 작업 내용·수리 전후 사진을 함께 확인할 수 있어야 한다. | 추천 카드 또는 상세 화면에서 사례와 담당 기사의 연결을 확인할 수 있다. |
| FR-MAT-03 | 추천 근거 제공 | AI는 현재 증상과 사례의 최초 증상·확인 원인·작업 내용·부품 중 관련 있는 정보를 근거로 추천 사유를 설명해야 한다. | 설명을 원본 사례와 대조할 수 있고, 사례에 없는 작업 경험이나 부품이 추가되지 않는다. |
| FR-MAT-04 | 기본 조건 판별 | 해당 작업 항목에 대한 기사 전문 분야·활동 지역·방문 가능 조건을 등록 데이터로 검사하고 요청 소유 계정의 기사는 제외한다. 서울 전역의 동 단위 이동 기준을 적용하며 복수 분야의 일치·미지원 분야를 구분한다. | 일부 분야가 맞는 기사를 모든 분야 처리 가능으로 표시하지 않는다. 다른 항목의 예약도 기사 일정 검사에 포함하며 이동자료 누락을 적합으로 처리하지 않는다. 같은 계정의 기사로 자기 요청의 어떤 항목에도 참여할 수 없다. |
| FR-MAT-05 | 사례 비교·기사 선택 | 사용자는 기사 프로필, 연관 사례, 추천 근거, 방문 가능 조건을 비교하고 상담할 기사를 선택할 수 있어야 한다. 유사 사례가 현재 문제의 동일 원인을 확정하지 않는다는 점을 안내해야 한다. | 사례와 현재 문제를 비교한 뒤 기사를 선택할 수 있고, 추천만으로 접수 자료가 모든 기사에게 전달되지 않는다. |
| FR-MAT-06 | 후보 부족·일반 후보 안내 | 연관 사례·시연 자료가 없는 상태와 실제 조건에 맞는 기사가 없는 상태를 구분한다. 사례가 없어도 등록 분야·지역으로 일반 후보를 추천하여 직접 연락·상담 선택을 허용한다. 소요 시간 등이 미확인이면 이를 표시하고 기사 확인 후 일정 적합성을 검사한다. | 사례 점수·경험을 만들어내거나 시간 미확인을 예약 가능으로 표시하지 않는다. 시연 자료가 없는 제품도 기사 확인 조건과 작업·이동 검사를 통과하면 예약한다. 실제 적합 후보가 없을 때 보완·재탐색을 안내하며 긴급 안내를 유지한다. |

사례 추천과 일반 후보에는 확인된 조건과 미확인 조건을 구분해 표시한다. 조건 충족 판정·예약 확정은 필요한 검사를 마친 경우에만 허용한다. **공개 연락 목록은 FR-CON-05의 별도 경로**이며 사례가 없거나 일정·이동 자료가 미등록·부적합해도 직접 문의할 수 있다. 공개 연락 목록에 나타났다는 이유로 예약 조건 충족·즉시 방문 가능으로 표시하지 않는다.

### 4.6 직접 연락 및 요청 검토·상담

**주체:** 사용자, 기사, 시스템 · **근거:** 제4.1절, 제4.2절, 제5.2절, 제7.4절

| ID | 기능명 | 요구사항 | 확인 기준 |
| --- | --- | --- | --- |
| FR-CON-01 | 선택 기사에게 상담 요청 | 사용자는 작업 항목별로 상담 상대와 필요한 사진·증상·경과 요약의 공개 범위를 선택한다. 복수 기사를 개별 선택할 수 있으며 추천·참여 의사는 사용자 선택을 대신하지 않는다. | 상담은 항목 하나에 연결한다. 같은 기사와 여러 항목을 상담해도 자료·권한·이력을 구분한다. 다른 항목에서 선택됐다는 이유로 비공개 자료를 공개하지 않는다. |
| FR-CON-02 | 상담 수락·거절·종료 | 기사는 항목별 상담을 수락·거절한다. 거절·종료·선택 해제 시 해당 상담의 미확정 견적은 선택 불가가 된다. **선택 반영:** 예약 취소·완료·중단 시 해당 상담과 선택 관계도 종료한다. | 예약 확정 시 같은 항목의 경쟁 상담만 종료한다. 재상담은 새 선택·공개 범위 확인·기사 수락·견적 발행을 거치며 이전 견적은 복원하지 않는다. 다른 항목은 유지하고 상담 종료로 예약을 우회 취소하지 않는다. |
| FR-CON-03 | 외부 상담 후 자료 보완 | 기사의 추가 질문·사진 보완 요청은 공개 연락수단을 통한 외부 상담으로 진행한다. 사용자는 확인한 사실·설명과 본인 사진을 기존 요청·작업 항목에 보완하고 전달 범위를 확인한다. 사용자·기사 간 질문·답변 대화는 앱에 등록·저장하지 않는다. 사실·제안 변경은 제6.2절을 따른다. | 공통 장소 변경, 한 항목의 수량 변경, 한 기사 제안 변경, 참고 자료 추가를 구분한다. 사용자 보완 사진은 요청 전체 한도를 적용하고 공개 범위를 확인한 자료만 선택 기사에게 제공한다. 사용자-AI 문답과 기사 방문 준비사항 등록은 유지한다. |
| FR-CON-04 | 상담 관계·전달 이력 확인 | 사용자와 기사는 참여한 작업 항목의 선택·수락·종료 상태, 허용된 전달 자료·견적을 조회한다. 외부 대화 내역은 저장·조회하지 않는다. 다른 기사 관계의 자료는 공개하지 않으며 종료 후에는 제6.3절을 따른다. | 같은 기사의 다른 활성 예약 권한으로 종료 관계의 후속 기록을 열람할 수 없다. 한 관계 종료가 다른 항목의 정당한 열람 권한을 없애지 않는다. |
| FR-CON-05 | 일반·긴급 직접 연락 | **선택 반영:** 사용자는 기사 공개 표시명·분야·활동 지역·업무 연락수단을 조회하고 전화·외부 연락으로 문의할 수 있다. 기사는 해당 연락에 응답하여 상담·방문·금액·수리를 직접 협의할 수 있다. | 로그인·요청 생성·사진·AI·방문 조건·사례 점수·상담 수락·견적·예약을 선행 조건으로 요구하지 않는다. 일반·긴급 및 앱 이용 도중에도 제공하며 기사 공개 범위 밖 개인정보·일정·다른 요청을 공개하지 않는다. 연락만으로 앱 상담·예약·점유·완료 기록을 생성하지 않는다. |
| FR-CON-06 | 직접 연락 후 선택적 기록·앱 이용 | **선택 반영:** 직접 연락만으로 진행하거나 필요한 앱 기능을 선택할 수 있다. 기존 요청이 있으면 해당 항목에 직접 연락으로 해결·미해결한 결과를 사용자 진술로 기록할 수 있다. 앱 상담·예약으로 전환하려면 해당 기능의 입력·확인·조건 검사를 적용한다. | 외부 연락 결과를 앱이 확인한 예약·완료 실적으로 바꾸지 않는다. 연락 결과 기록이나 앱 전환은 필수가 아니며 기록을 위해 새 요청 생성을 강제하지 않는다. 기존 활성 상담·예약은 자동 종료하지 않고 전체 종료는 FR-REQ-11을 따른다. |

| FR-QTE-04 | 제안 비교·선택 | 사용자는 같은 작업 항목의 기사 정보·작업 범위·방문 시간·비용·할인·추가 비용 조건을 비교하고 제안을 선택한다. | 동일한 비교 항목으로 차이를 확인하며 다른 작업 항목의 견적을 경쟁 제안으로 섞지 않는다. 선택 제안은 해당 항목의 예약에 연결된다. |
| FR-QTE-05 | 견적 유효성·수정 관리 | 기사는 방문 시작 이하의 유효 종료 시각을 지정한다. 수정본은 새 버전으로 발행한다. 만료·철회·거절·상담 종료·전제 변경 또는 같은 항목의 다른 제안 확정으로 무효화된 제안은 선택할 수 없다. | 공통·항목·기사 제안별 버전과 상태를 표시한다. 다른 항목 확정만으로 견적을 무효화하지 않는다. 재상담에도 이전 견적은 복원하지 않는다. 확정 합의는 견적 수정·만료로 바뀌지 않으며 별도 예약 변경·진행 중 합의를 따른다. |

| FR-HIS-01 | 경과 타임라인 | 동일 문제의 사진·증상·시도한 조치·결과를 날짜별로 연결하여 시간순으로 조회할 수 있어야 한다. | 각 기록에서 날짜와 대응 사진·설명을 확인할 수 있고, 추가 기록을 넣어도 기존 경과가 유지된다. |
| FR-HIS-02 | 재촬영 가이드 | 동일 부위를 유사한 구도와 거리에서 촬영하도록 안내해야 한다. | 사용자가 기존 사진을 참고해 같은 부위를 다시 촬영할 수 있는 안내를 확인한다. |
| FR-HIS-03 | 비교 가능 여부 판별 | AI는 촬영 구도·조명 차이 등을 고려해 사진 간 비교 가능 여부를 판별해야 한다. 비교가 어려우면 판단을 유보하고 재촬영을 안내해야 한다. | 비교 가능한 사진과 직접 비교가 어려운 사진을 구분하며, 후자를 실제 악화로 단정하지 않는다. |
| FR-HIS-04 | 관찰 변화 표시 | **선택 반영:** 벽지 물자국 사진의 비교 결과와 변화 영역을 사진 식별자에 연결한 사각형 좌표·설명으로 반환한다. 좌표 기준·범위는 제6.6절을 따른다. 면적·색상은 관찰 가능한 변화만 설명한다. | 변화 있음·변화 없음·비교 불가를 구분하고 원인 미확인을 별도로 표시한다. 변화 없음에는 허위 사각형을 만들지 않는다. 변화 유무·근거가 맞더라도 영역·설명이 틀리면 정확성 실패로 판정한다. |
| FR-HIS-05 | 사진 근거 연결 | 경과 설명 항목마다 근거가 되는 사진과 촬영 날짜를 연결해야 한다. | 요약의 변화 설명에서 해당 원본 사진·날짜를 확인할 수 있고 잘못된 사진을 근거로 연결하지 않는다. |
| FR-HIS-06 | 외형 변화·원인 분리 | 사진에서 보이는 변화와 내부 고장 원인·위험도 추정을 구분하여 표시해야 한다. | 물자국이 넓어진 관찰 사실만으로 특정 내부 원인이나 위험도를 확정하지 않는다. |
| FR-HIS-07 | 단일 사진·후속 보강 | 사진 한 장과 기본 정보만으로 요약·인계를 진행할 수 있어야 한다. 자료 추가·변경 시 관련 결과에 갱신 필요를 표시한다. 비용이 발생하는 AI 재분석·요약 재생성은 사용자가 요청할 때만 수행하고 새 초안은 확인 후 반영한다. | 사진쌍 부족은 상담·예약을 막지 않는다. 자료 추가·조회·공유 범위 변경으로 자동 재분석하지 않는다. 사용자가 직접 요약을 정정·확인할 수 있으며 갱신 필요 요약을 새 확정 전달본으로 제공하지 않는다. |
| FR-HIS-08 | 사진·기록·요약 정정 | **선택 반영:** 본인 사진·촬영일, 증상·발견일, 조치·결과를 정정하면 현재 값을 덮어쓰고 최종 수정일을 갱신한다. 요약 정정은 사용자 확인 후 현재 요약에 반영한다. 내용 수정 이력·이전 값 복원은 제공하지 않는다. | 촬영일·발견일은 실제 경과 날짜로 유지하며 수정일로 대체하지 않는다. 파생 결과의 낡음 판별용 식별값과 견적·예약 합의 버전은 제6.6절에 따라 별도 유지한다. |
| FR-HIS-09 | 동일 부위 묶음·비교 사진 선택 | **선택 반영:** 사용자가 같은 부위의 사진을 묶는다. 촬영 날짜를 확인한 최초·최신 사진을 기본 비교하고, 사용자가 같은 묶음의 서로 다른 두 사진으로 변경할 수 있다. | 날짜 미확인 사진은 기본 비교에서 제외한다. 수동 선택 시 날짜 미확인·동일 날짜의 시간 순서 불명을 표시하고 경과 방향을 단정하지 않는다. 서로 다른 부위는 한 비교쌍으로 확정하지 않는다. |
| FR-HIS-10 | 근거 변경과 결과 재확인 | 사진·날짜·설명·비교쌍의 변경·삭제 시 관련 분석·요약·인계에 갱신 필요를 표시한다. AI 재분석·재생성은 사용자 요청 시에만 실행하며 직접 요약을 정정·확인할 수도 있다. 공개 범위·가림만 변경되면 전달본·PDF의 확인만 무효화하고 원본 분석은 유지한다. | 자료 변경만으로 AI를 다시 호출하지 않는다. AI 실행 중 또는 확정·전달 직전 근거가 바뀌면 이전 결과의 확정·전달을 차단한다. 늦은 결과가 최신 요약을 덮어쓰거나 삭제 사진을 다시 연결하지 않는다. |

### 4.11 인계서·외부 공유 및 방문 준비

**주체:** 사용자, 기사, AI, 시스템 · **근거:** 제4.1절, 제5.1절, 제5.2절, 제6.3절, 제7.4절

| ID | 기능명 | 요구사항 | 확인 기준 |

| FR-HND-01 | 인계서·보고서 생성 | 발견 위치·시점, 발생 조건, 날짜별 근거 사진·촬영일·관찰 변화, 시도한 조치·결과·미확인 사항을 연결한다. **의도 정정:** 앱에서는 사진·그림과 Markdown 본문을 함께 표시한다. | 해당 작업 항목의 내용과 요청 공통 자료를 구분하고 입력된 사실·사진 근거를 연결하며 미입력 사실은 미확인으로 표시한다. AI의 분야 후보만으로 별도 작업 내용을 만들어 넣지 않는다. |
| FR-HND-02 | 보고서 검토·수정·확정 | 사용자는 인계·공유할 최신 사진·본문·촬영일·관찰 설명과 공개 범위를 확인한다. 근거·본문·범위 변경 시 기존 확인을 무효화하고 새 초안 또는 직접 수정본을 다시 확인한다. | 현재 보고서는 확인 후 교체한다. 검토 전 초안·삭제 근거·가림 실패 자료를 확정·전달·PDF 추출하지 않는다. 본문 수정 이력은 쌓지 않으며 제6.6절의 최신 자료 검사를 적용한다. |
| FR-HND-03 | 확정 기사에게 사전 인계 | 해당 항목의 예약 확정 기사에게 사용자가 확인한 최신 경과·인계서와 필요한 상세 방문 정보를 제공한다. | 같은 요청의 다른 항목에 대한 권한은 자동 부여하지 않는다. 해당 상담 요약·인계 기록을 방문 준비에 활용하며 관계별로 공개 범위를 검사한다. |
| FR-HND-04 | 사진 포함 PDF 추출·공유 | **의도 정정:** 앱에서 공유 범위를 확인한 보고서를 사진·그림과 Markdown을 렌더링한 본문이 포함된 PDF로 추출한다. 사진 식별자·확인 촬영일 또는 미확인 표시·관찰 설명·기존 변화 표시를 연결한다. | 가림·자료 제외·메타데이터 제거·사용자 확인 후 추출한다. 상세 주소·연락처·상담·견적·비공개 원본 접근 주소·가림 전 원본을 포함하지 않는다. 생성 중 정정·삭제 시 낡은 PDF를 제공하지 않으며 수정 후 새 파일을 만든다. 이미 내려받은 파일은 자동 회수·갱신하지 않는다. |
| FR-HND-05 | 외부 추가 확인·방문 준비사항 | 기사는 인계서를 확인하고 필요한 질문·사진 보완을 전화·외부 연락으로 요청한다. 사용자는 접수 자료를 보완하고, 기사는 장비·부품·현장 점검 등 준비사항을 해당 항목·예약에 등록한다. | 사용자가 공개 확인한 보완 자료와 기사 준비사항을 조회한다. 앱 내 질문·답변 대화를 제공하지 않으며 한 항목의 보완을 다른 관계에 자동 전달하지 않는다. 사진 삭제 후에는 남은 근거로 재확인한다. |

### 4.12 작업 완료 및 수리 기록

**주체:** 기사, 사용자, 시스템 · **근거:** 제4.1절, 제4.2절, 제5.2절, 제7.4절

| ID | 기능명 | 요구사항 | 확인 기준 |
| --- | --- | --- | --- |
| FR-WRK-01 | 작업 완료 처리 | 담당 기사는 실제 시작이 기록되고 중단 요청이 없는 예약의 완료를 처리한다. 서버 처리 시각을 실제 종료로 기록하고 실제 종료 위치·수행 내역을 확인한다. | 시작 전·취소·중단 예약은 완료할 수 없다. 해당 항목의 완료·상담 종료·일정 재검사·권한 변경을 함께 반영하고 다른 항목은 유지한다. 요청 전체 종료는 FR-REQ-11의 확인을 거친다. |
| FR-WRK-02 | 수행 내역 등록·조회 | 기사는 해당 항목·예약에서 확인한 원인·실제 작업·부품을 수행 내역으로 기록한다. 중단 시 수행·미수행·미확인을 구분하며 반영된 변경 합의와 연결한다. **의도 정정:** 기사 사진은 FR-PRO-03에 따라 본인 프로필의 포트폴리오에 저장하며 요청·예약의 수행 기록에 업로드하지 않는다. | AI 추정과 현장 확인을 구분한다. 완료·중단 후 해당 관계의 종료본만 기사에게 제공한다. 기존 합의와 이후 변경을 보존하고 다른 항목의 자료·권한을 섞지 않는다. 기사 프로필 사진이 요청 이력·인계서에 자동 첨부되지 않는다. |
| FR-WRK-03 | 실제 접수자료의 별도 활용 차단 | **선택 반영:** 실제 접수·완료·중단 자료를 공개 포트폴리오나 별도 AI 학습·분석 자료로 전환하는 기능은 이번 시연에서 제외한다. 사례·평가는 별도로 준비한 모의·재현자료를 사용한다. | 작업 종료나 기본 전달 확인으로 실제 접수자료가 공개·별도 활용되지 않는다. 전환용 동의 절차를 구현 의무로 남기지 않으며 중단을 완료 실적으로 표시하지 않는다. |
| FR-WRK-04 | 실제 작업 시작·조기 시작 동의 | 담당 기사는 유효한 확정 예약에서 같은 기사의 다른 진행 작업·이동·일정 충돌을 검사한 뒤 시작한다. **선택 반영:** 예정 시각 전에는 해당 예약·조건에 대한 사용자 동의를 받는다. | 변경·취소·철회된 동의는 재사용하지 않는다. 같은 기사 동시 시작은 차단하며 실제 시각은 서버 시각이다. 조기 시작 동의에 30분 준비시간을 다시 요구하거나 예상 종료를 자동 앞당기지 않는다. 시작 후 일반 취소·예약 변경은 차단하되 FR-WRK-08은 허용한다. |
| FR-WRK-05 | 작업 중단 요청·처리 | 시작 후 사용자는 사유와 함께 중단을 요청하고 담당 기사는 확인하거나 직접 중단한다. 서버 처리 시각을 실제 종료로 저장하며 사유·수행 내역·종료 위치를 기록한다. | 사용자 요청만으로 점유를 해제하지 않는다. 실제 중단 후 해당 상담을 종료하고 해당 항목만 재탐색으로 돌린다. 다른 항목은 유지하며 이동·후속 일정 재검사 후 남은 시간을 개방한다. 중단을 완료로 바꾸지 않는다. |
| FR-WRK-06 | 예상 시간 초과·종료 예상 갱신 | **선택 반영:** 진행 중 작업이 유효한 종료 예상에 도달해도 끝나지 않으면 초과로 표시한다. 기사가 새 종료 예상을 입력하기 전에는 해당 기사·한국 날짜의 당일 신규 예약 확정을 막고 후속 예약의 충돌·확인 필요를 표시한다. | 미래 종료 예상 갱신 또는 실제 종료 후 최신 작업·이동 일정으로 재검사한다. 충돌 여부와 근거를 양측 예약 조회에 표시하며 기존 예약을 자동 이동·취소하지 않는다. 갱신 후에도 충돌 구간은 신규 확정하지 않는다. |
| FR-WRK-07 | 조기 완료·중단 후 시간 개방 | **선택 반영:** 실제 종료 위치·서버 종료 시각에서 다음 일정까지의 이동시간을 적용하여 재검사한 뒤 남은 시간을 개방한다. | 예약상 종료 시각만 지우고 즉시 빈 시간으로 표시하지 않는다. 재검사 완료 전·이동 자료 누락·30분 준비시간 미충족 구간은 신규 예약할 수 없고 후속 예약 조건은 유지한다. |
| FR-WRK-08 | 진행 중 작업 변경 합의 | **선택 반영:** 실제 시작 후 해당 항목의 범위·금액·예상 종료 변경안을 양측이 같은 버전으로 확인하고 후속 충돌 해소 후 반영한다. 협의 중에는 수행 가능한 기존 합의 범위만 진행한다. | 추가·변경 작업은 합의 반영 후 수행한다. 거절·철회는 기존 조건을 유지하고 재수정에는 새 수락이 필요하다. 실제 시작·이전 합의를 덮어쓰지 않고 일반 취소를 다시 허용하지 않는다. 실제 초과 기록과 계약 변경을 구분하며 완료·중단과 경합해도 유효한 전이만 반영한다. |

## 6. 상태와 처리 규칙

### 6.1 요청·작업항목 처리 단계

아래 상태 명칭은 기획서의 흐름을 구현하기 위한 **명세화 예시**이다. **선택 반영:** 하나의 요청 아래 작업항목을 두고 각 항목에 상담·견적·예약을 연결한다. 작업항목은 사용자가 확인한 작업 종류·부위·범위로 구분하며 같은 분야의 다른 작업도 별도 항목으로 관리한다. 최초에는 기본 항목 하나로 진행할 수 있고 AI의 복수 분야 후보를 자동으로 여러 작업항목으로 확정하지 않는다. 한 견적과 한 예약은 각각 하나의 작업항목만 대상으로 한다.

접수·분석과 요청 전체 종료를 제외한 아래 진행 단계는 작업항목별로 관리한다. 화면 명칭이나 내부 저장 값은 달라도 되지만 각 항목의 의미·진행 조건을 구분하고 요청 조회에서 함께 보여준다. 사진·문답·경과는 요청에 연결하되 이를 사용하는 작업항목과 전달 범위를 구분한다. 작업항목 추가·수정은 다른 항목의 상태를 바꾸지 않으며, 이미 합의한 범위의 변경은 제6.2절을 따른다.

**직접 연락은 아래 단계와 독립적으로 이용한다.** 요청 생성 전이나 어느 진행 단계에서도 공개 연락수단으로 문의할 수 있다. 연락수단 조회·사용만으로 활성 상담·예약·점유를 만들거나 기존 상태를 바꾸지 않는다. 외부 해결 결과를 남기는 경우에는 사용자 진술로 기록하며 기존 활성 관계와 요청 전체 종료는 원래 절차를 따른다.

**명세화:** 요청 전체 상태, 작업항목 상태와 개별 상담·예약 상태는 분리한다. 예약 취소·작업 완료·중단 확정 시 해당 예약의 상담도 종료하고 현재 선택과 미확정 견적을 정리한다. 취소·중단된 항목은 재탐색으로 돌아가며 새 상담 선택·수락·견적 발행을 거친다. 다른 작업항목의 상담·예약·권한은 유지한다. 기존 사진·문답·경과는 재사용하되 이전 기사에게 새 기록이 자동 공개되지는 않는다.

사용자의 전체 종료 확인은 활성 관계를 자동 취소하거나 진행 중 작업을 완료시키지 않는다. 활성 관계가 남으면 해당 항목과 필요한 종료 절차를 안내한다. 모든 관계가 정리된 뒤 사용자 확인과 상태 저장을 함께 검사하여 요청 전체를 종료하며, 일부 항목만 완료되거나 예약이 취소되었다는 이유로 전체 종료하지 않는다.

**긴급 안내와 기사 직접 연락은 정상 분석 흐름과 독립적으로 제공한다.** 사용자 긴급 표시 또는 사전에 정한 긴급 입력이 있으면 검증된 정적 대응 안내와 공개 연락 경로를 우선 제공한다. 등록 분야·활동 지역·공개 업무 연락수단을 확인하여 문의할 수 있게 하며, 분야·지역을 모르면 공개 목록에서 직접 선택할 수 있다. 로그인·접수·AI·사례 점수·빈 일정·이동시간 검사·30분 준비시간은 연락의 조건이 아니다. 연락 가능한 등록 기사가 없는 경우와 실제 방문 가능 여부가 미확인인 경우를 구분하고, 등록된 공식 대안 경로를 제공한다. 연락처가 있다는 이유로 즉시 방문을 보장하거나 할인 대기를 우선 권하지 않는다.

### 6.2 예약·견적 일관성 규칙

상태 전이·버전·시간 검사·점유 처리는 **명세화 규칙**이다. 요청 공통 사실·작업항목 사실·기사별 조건의 분리, 작업항목별 예약, 한국 시간·15분 입력·30분 준비, 조기 시작과 실제 작업시간·진행 중 합의 처리는 **선택 반영**이다.

이 절은 앱의 견적·예약·작업 관리 기능을 이용하는 경우에 적용한다. 직접 연락으로만 협의한 시간·금액은 앱 예약이나 일정 점유로 자동 반영하지 않는다. 앱 예약으로 전환할 때에는 일반·긴급 모두 아래 검사를 적용하고, 기사가 외부 일정을 등록할 때에도 FR-PRO-05의 기존 예약 보호 규칙을 따른다.

**상담과 견적의 유효성**

1. 상담 수락, 견적 제안, 예약 확정은 별개이다. 기사 참여 의사는 방문·금액 확약이 아니다. 해당 작업항목에서 사용자가 선택한 상대가 수락한 활성 상담에서만 정식 견적을 발행하고 사용자가 선택한다. 자기 요청 참여는 모든 단계에서 차단한다.
2. 견적은 작업항목 식별자, 요청 공통 사실·작업항목 사실·해당 기사 제안의 버전을 참조한다. 수정 견적을 새 버전으로 발행하면 해당 이전 견적은 대체됨으로 처리한다. 최소 발생 출장·진단비와 확정 항목의 합계는 금액으로, 미확정 부품·추가 작업은 항목·발생 조건으로 구분한다. 이를 무조건적인 최종 수리비로 표현하지 않는다.
3. 철회·사용자 거절·만료 또는 같은 작업항목의 다른 제안으로 예약 확정 시 미확정 견적은 선택 불가가 된다. 예약 확정은 같은 항목의 경쟁 상담만 종료한다. 상담 거절·종료·선택 해제는 해당 상담의 미확정 견적만 무효화하며 다른 작업항목의 상담·견적을 유지한다. 재선택해도 이전 견적을 복원하지 않고 새 상담 선택·수락과 새 발행을 거친다.
4. 예약 확정 직전에 해당 항목의 활성 예약 유무, 최신 견적·세 단계의 전제 버전, 만료, 활성·수락 상담, 현재 사용자 선택과 필요한 방문시간 중복 확인을 함께 검사한다. 검사와 저장은 원자적으로 처리한다. 확정 당시 합의는 보존하며 이후 견적 수정·만료로 예약을 바꾸지 않는다. 확정 후 상담 해제로 예약을 우회 종료할 수 없다.

| 신규 확정·시작 전 예약 변경 시각 | 반영 직전 서버 시각으로 `방문 시작 > 현재 시각` 및 `방문 시작 - 현재 시각 >= 30분`을 모두 검사한다. 정확히 30분이면 허용하되 다른 조건도 충족해야 한다. 처리 도중 30분 미만이 되면 확정하지 않는다. 이미 확정된 예약의 동의된 실제 조기 시작과 진행 중 합의 변경에는 30분 준비시간을 다시 적용하지 않는다. |
| 작업항목별 활성 예약 | 같은 분야라도 다른 작업항목에는 각각 예약할 수 있지만 한 작업항목의 활성 예약은 하나이다. 방문 준비·작업 중·중단 요청은 활성이고 취소·완료·중단 확정은 제외한다. 한 견적·예약에 여러 작업항목을 묶지 않는다. |
| 기사 일정·실제 작업 충돌 | 최신 사용자 가능 조건, 개별 기사 일정, 작업 시간과 고정 이동표로 재검사한다. 작업 구간은 시작 포함·끝 제외이며 맞닿은 작업도 이동시간을 별도로 충족해야 한다. 같은 기사는 요청·항목이 달라도 일정 중복과 실제 동시 작업을 허용하지 않는다. 사용자 동의로 이 제한을 우회하지 못한다. |
| 같은 요청의 다른 기사 방문시간 중복 | 같은 요청의 서로 다른 작업항목에서 중복되는 예약·방문 구간을 사용자에게 제시하고 현재 조건 버전에 대한 중복 확인을 받아야 한다. 신규 확정·시간 변경·조기 시작·진행 중 합의로 중복 대상이나 구간이 달라지면 다시 확인한다. 같은 주소라도 별도 요청 사이에는 이 확인을 요구하지 않는다. 동일 기사 작업·이동 충돌 검사는 요청과 무관하게 유지한다. 기존 예약의 조건은 자동 변경하지 않으며 중복이 없으면 별도 확인은 요구하지 않는다. |
| 초과·재검사 상태 | 종료 예상 미갱신 초과 작업은 해당 기사 당일 신규 예약 확정을 막는다. 그 외에도 작업·이동 충돌 또는 재검사 미완료 구간은 신규 확정할 수 없다. 초과 규칙은 조회·확정 때 서버 현재 시각으로 적용한다. |

**조건 변경과 합의**

| 변경 대상 | 미확정 견적에 대한 영향 | 확정 예약에 대한 영향 |
| --- | --- | --- |
| 요청 공통 사실: 여러 항목이 공유하는 실제 작업 장소·지역 등 | 공통 버전을 갱신하고 해당 사실을 참조하는 모든 작업항목의 미확정 견적을 재확인 필요로 전환한다. 관련 추천을 다시 계산하며 새 전제를 확인한 재발행 견적만 선택한다. | 예약별로 변경안을 만들고 각 예약의 합의·재검사 전에는 기존 장소·조건을 유지한다. 일부 예약만 동의하면 예약별 합의 장소와 변경 대기를 구분한다. 진행 중 작업의 실제 장소를 소급 변경하지 않는다. |
| 작업항목 사실: 확인 분야·문제 부위·작업 종류·수량·제품 조건·방문 가능 조건 | 해당 항목 버전과 관련 견적만 재확인·재발행 대상으로 바꾼다. 다른 작업항목의 견적·예약은 유지한다. | 해당 항목의 예약 변경안에만 적용한다. 합의 전 기존 조건을 유지하고 시작 후에는 진행 중 작업 변경 절차를 적용한다. |
| 특정 기사 제안: 해당 항목의 작업 범위·소요 시간·방문 시각·금액·조건 | 해당 항목·기사의 견적만 새 버전으로 발행·재검사한다. 다른 기사와 같은 기사의 다른 항목 견적, 요청 공통·항목 사실 버전은 유지한다. | 해당 예약 변경안에만 적용한다. 기존 확정 조건은 합의 전까지 유지한다. |
| 참고 사진·설명·요약 정정·추가·삭제 | 참조하는 분석·인계는 갱신·재확인 필요로 바꾸지만 작업 사실이 바뀌지 않으면 견적을 일괄 무효화하지 않는다. 사실 변경이 확인되면 위의 해당 범위를 적용한다. | 요약 정정·사진 삭제만으로 예약 합의를 바꾸거나 예약을 취소하지 않는다. 합의 전제가 바뀌면 해당 예약의 변경 절차를 적용한다. |

외부 상담으로 사실 변경을 확인하면 사용자가 앱의 요청 공통 사실 또는 해당 작업항목 사실에 반영한다. 기사 한 명의 제안 수정만으로 다른 항목·기사에게 사실 변경을 전파하지 않는다. 자료 삭제는 제6.7절을 따르며 본인 사진 삭제를 활성 상담·예약 때문에 거절하지 않는다.

1. 시작 전 예약 변경은 요청자가 새 조건을 확인하고 상대가 같은 버전을 수락한 뒤 최신 시간·작업·이동 조건과 필요한 방문시간 중복 확인을 재검사하여 반영한다. 원견적의 사후 만료는 변경 거절 사유가 아니다.
2. 협의 중·거절·철회 시 기존 조건과 점유를 유지한다. 재수정하면 이전 수락을 재사용하지 않는다. 상세 주소 변경도 예약별로 이 절차를 따르며 같은 장소의 연락처 정정은 사용자 확인 후 해당 활성 예약의 담당 기사에게 반영한다.
3. **진행 중 작업 변경:** 사용자 또는 담당 기사는 해당 항목의 추가 작업·부품 확정 등 범위·금액·예상 종료 변경을 제안할 수 있다. 새 범위·수량·확정 및 미확정 비용·예상 종료·필요한 사용자 가능 조건과 기준 예약 버전을 표시하고 양측이 같은 변경안 버전을 수락해야 한다. 실제 시작 시각을 바꾸거나 새 작업항목을 기존 예약에 합치지 않는다.
4. 진행 중 변경은 반영 직전 중단 요청·종료 여부, 최신 합의, 현재 시각보다 미래인 예상 종료, 변경안으로 확인한 사용자 가능 조건, 기사 후속 작업·이동과 다른 기사 방문시간 중복 확인을 재검사한다. 같은 기사 후속 일정과 충돌하면 변경안을 반영하지 않고 별도 예약 변경·취소 등으로 충돌을 먼저 해소해야 한다. 상대 예약을 자동 이동·취소하지 않는다.
5. 진행 중 변경의 협의·거절·철회·검사 실패 동안은 기존 합의 범위만 수행한다. 새 범위·금액·예상 종료는 합의와 재검사가 완료된 때 함께 반영한다. 중단 요청 중·종료 후에는 변경안을 확정하지 않으며 재수정 시 다시 동의받는다. 실제 지연·초과는 합의 불성립을 이유로 숨기지 않고 아래 운영 규칙으로 기록한다.
6. 확정 예약과 충돌하는 외부 일정 추가·수정·가능 시간 축소는 거절한다. 기존 예약의 적법한 변경·취소 후 반영한다. 실제 작업 초과에 대한 운영상 종료 예상 갱신은 사실 확인과 일정 재검사이며 합의 범위·금액 변경을 대신하지 않는다.

**비용과 할인 비교**

같은 기사·같은 작업 범위·수량·확정 비용 항목의 할인 전 금액을 B, 할인 후 금액을 A로 둔다. `할인액 = B - A`, `할인율 = (B - A) / B × 100`이며 원 단위 금액과 소수 첫째 자리까지의 할인율을 제공한다. B가 0이면 할인율은 `해당 없음`이고, 할인 없는 제안은 B=A·할인액 0원으로 표시한다. 금액은 음수를 허용하지 않으며 할인 제안은 A≤B를 만족해야 한다. 미확정 비용은 양쪽 비교 합계에서 제외하되 동일한 항목·조건을 함께 보여준다. 범위 축소·부품 제외·다른 기사 가격을 할인 근거로 사용하지 않는다.

**예약 취소와 실제 작업**

| 처리 | 허용 주체·사전 상태 | 반영 결과 |
| --- | --- | --- |
| 예약 취소 | 사용자 또는 담당 기사. 실제 시작 전이며 기사는 사유를 입력한다. 상대 승인은 요구하지 않는다. | 해당 예약 점유 해제·상담 종료·작업항목 재탐색·이력 보존·권한 축소를 함께 반영한다. 다른 항목의 상담·예약은 유지한다. 예정 시각이 지났어도 실제 시작 전이면 가능하다. |
| 작업 시작 | 담당 기사. 취소·종료되지 않은 확정 예약이며 다른 실제 진행 작업·중단 요청 작업이 없고 기사 일정·이동 조건과 필요한 사용자 방문시간 중복 확인을 충족한 상태 | 조기 시작이면 최신 예약 조건에 연결한 사용자 동의를 추가 검사한다. 버튼 요청 처리 서버 시각을 실제 시작으로 기록하며 이후 시작 전 취소·변경을 차단한다. 진행 중 변경은 별도 합의 절차로 처리한다. |
| 중단 요청 | 사용자. 실제 작업 중 | 사유·요청 상태를 기록한다. 실제 중단 전까지 점유·합의 조건을 유지하며 완료 처리는 차단한다. |
| 중단 확정 | 담당 기사. 사용자 요청 확인 또는 직접 사유를 남긴 중단 | 버튼 요청 처리 서버 시각·실제 종료 위치·수행 및 미수행 내역을 기록한다. 해당 상담을 종료하고 해당 항목만 재탐색으로 복귀시키며 관계별 권한을 축소한다. 완료 실적으로 표시하지 않는다. |
| 작업 완료 | 담당 기사. 중단 요청 없는 작업 중 | 버튼 요청 처리 서버 시각·실제 종료 위치·수행 내역을 기록하고 해당 상담 종료·완료 권한을 함께 반영한다. 다른 항목을 종료하지 않으며 취소·중단 예약에는 적용하지 않는다. |

**조기 시작:** 사용자는 현재 예약 버전과 조기 시작 대상·시간을 확인하여 동의하거나 철회한다. 동의는 해당 실제 시작 한 번에만 적용하고 예약 조건 변경·취소·동의 철회 시 무효화한다. 시작 직전에 동의의 현재 유효성, 같은 기사의 다른 진행 작업 부재와 기존 일정 충돌, 앞선 실제 종료 위치·시각에서의 이동 가능 여부, 새로 생기는 다른 기사 방문시간 중복 확인을 함께 검사한다. 30분 준비시간을 다시 요구하거나 실제 서버 시각을 15분 단위로 반올림하지 않는다. 조기 시작만으로 합의 범위·금액·예약 예상 종료를 변경하거나 종료 예상을 자동으로 앞당기지 않는다.

실제 시작·완료·중단 시각은 클라이언트에서 입력하거나 예정 시각으로 대체하지 않는다. 반복 요청으로 실제 시각을 덮어쓰거나 종료 기록을 중복 생성하지 않는다. 같은 기사의 여러 예약 시작, 시작·취소·조기 동의 철회, 완료·중단 요청, 완료·직접 중단, 진행 중 변경 확정·종료 등이 경합하면 최신 상태·합의·기사 자원을 함께 확인하여 허용된 전이만 원자적으로 반영한다. 중단 요청 자체는 실제 종료가 아니다. 종료 시 미확정 변경안과 해당 상담의 미확정 견적은 선택 불가로 정리한다.

**예상 시간 초과와 남은 시간 개방**

1. 진행 중 또는 중단 요청 중 작업이 현재 종료 예상에 도달해도 실제 종료하지 않았으면 초과이다. 최초에는 예약 예상 종료를 사용하며 조기 시작만으로 당기지 않는다. 합의 변경으로 정한 종료 예상과 실제 지연에 대한 운영상 갱신의 출처를 구분한다. 기사가 종료 예상을 갱신하기 전까지 해당 기사의 한국 날짜 기준 당일 신규 예약 확정을 막는다. 날짜가 바뀌어도 미종료·미갱신이면 새 당일에 적용한다. 다음 날 예약도 작업 종료 불명으로 충돌 판단을 할 수 없으면 확정하지 않는다.
2. 초과 상태에서는 후속 예약의 예약 시각을 유지하고 충돌·확인 필요를 표시한다. 종료 미확정으로 확답할 수 없는 후속 일정은 충돌 가능으로, 이미 도달 불가능한 일정은 충돌로 구분한다. 자동 이동·취소하지 않는다.
3. 담당 기사가 실제 지연에 대해 현재 서버 시각보다 미래의 15분 단위 운영상 종료 예상을 갱신하면 실제 작업 위치·고정 이동시간으로 후속 일정을 재검사한다. 이 갱신은 사실대로 저장하되 합의 범위·금액을 변경하지 않는다. 확인된 기사 충돌과 사용자 확인 범위를 벗어난 같은 요청의 다른 기사 방문 중복을 표시하며 다른 예약을 자동 변경하지 않는다. 충돌 없는 구간만 준비시간 등 조건을 충족할 때 신규 확정할 수 있고, 갱신한 예상도 초과하면 같은 제한을 다시 적용한다.
4. 조기 완료·중단을 포함한 실제 종료 후에는 해당 작업의 지역 대표 위치를 종료 위치로 확인하고 실제 서버 종료 시각부터 다음 방문·복귀까지 이동 가능 여부를 다시 검사한다. 종료 위치가 달라졌으면 지원되는 대표 위치로 확인한다. 위치·이동 자료 누락 또는 재검사 미완료 시 개방하지 않는다.
5. 재검사 후 실제 작업이 끝난 잔여 구간만 개방한다. 신규 예약에는 종료 위치에서의 이동, 사용자 가능 조건, 15분 단위·30분 준비시간을 다시 적용한다. 실제 초과로 이미 발생한 후속 충돌은 표시하며 기존 예약 변경·취소는 당사자 절차를 따른다.

일정 갱신·시작·종료·확정·삭제가 경합해도 상태·점유·합의·권한이 함께 일치해야 한다. 취소·중단·완료는 기록 자동 삭제가 아니며 개별 삭제는 제6.7절에 따른다. 결제·환불·정산은 포함하지 않는다.

### 6.3 정보 전달 단계

기획서 제7.4절의 기본 전달을 아래와 같이 구체화한다. 필드·전이·종료 후 권한은 **명세화**, 별도 활용 제외·수동 가림은 **선택 반영**, 앱의 사진·Markdown 보고서 및 사진 포함 PDF 추출은 **의도 정정**이다. 상담·예약과 자료의 작업항목별 연결 및 사용자 확인 범위로 접근을 판단하며, 특정 필드가 필요하다는 이유로 요청 전체의 열람 권한을 부여하지 않는다.

기사 본인이 공개한 업무 연락수단은 아래 비공개 접수자료와 구분한다. 사용자는 공개 연락수단으로 문의하고 외부 연락 중 본인 연락처·방문 정보를 직접 알려줄 수 있으며 기사는 그 수단으로 응답할 수 있다. 앱은 저장된 사용자 연락처·상세 주소·사진을 연락 행위만으로 공개하지 않는다. 공개 연락수단 조회는 상담·인계 자료의 열람 권한을 부여하지 않는다.

| 임대인·관리사무소 공유 | 선택·확인한 관찰·증상·경과, 발견일·발생 조건·조치·미확인 사항과 가림 처리한 근거 사진, 사진 식별자·촬영일 | 사용자는 앱에서 사진과 Markdown 요약을 확인하고 같은 허용 범위의 사진 포함 PDF를 내보낸다. 상담·견적·상세 주소·연락처·원본 다운로드 주소는 제외한다. PDF 안의 사진·텍스트·파일 메타데이터에도 가림·제외 규칙을 적용하고 날짜를 모르면 미확인으로 표시한다. |
| 준비된 모의·재현 사례·평가 자료 | 별도로 구성하여 출처·사용 가능 여부·식별 정보 제거를 확인한 자료 | 실제 접수자료의 공개 포트폴리오·별도 AI 활용 전환과 그 동의 절차는 시연 제외이다. 준비된 자료의 확인 실패 시 사례 노출·평가 사용을 차단한다. |

앱의 동선 추천·상담·예약을 선택한 경우에는 다음 순서로 연결한다. 직접 연락에는 이 절차를 선행 조건으로 요구하지 않는다.

1. 사용자가 요청의 작업 지역과 항목별 방문 조건을 등록하고 동선 제안 탐색 대상 항목과 최소 공개 항목을 확인한다.
2. 시스템은 적합 작업항목을 기사에게 추천한다. 기사는 최소 정보로 해당 항목의 상담 참여 의사만 표시할 수 있다. 참여 의사는 견적이나 방문 확약이 아니다.
3. 사용자는 참여 의사를 표시한 기사의 프로필·사례를 확인하고 상담 상대를 개별 선택한다. **사례 탐색에서 기사를 직접 선택한 경우에는 작업 지역·방문 조건 등록은 유지하되, 동선 제안 탐색과 기사 참여 의사 단계를 생략하고 상담 요청으로 진행한다.**
4. 선택한 기사에게 허용된 사진·요약을 전달한다. 기사가 상담 관계를 수락하면 추가 확인은 공개 연락수단으로 진행하고 앱에서 정식 견적을 제안한다. 사용자·기사 간 질문·답변 대화는 저장하지 않는다.
5. 사용자가 해당 작업항목의 유효한 제안을 선택하고 상세 방문 정보와 제6.2절의 상담·견적·시간·충돌 및 필요한 방문시간 중복 확인 검사를 마치면 예약을 확정한다. 선택된 예약의 기사에게 상세 주소·연락처와 해당 항목의 최신 인계서를 제공한다.

원본과 전달본을 구분한다. **선택 반영:** 텍스트·사진·파일명에서 해당 단계에 금지된 식별 정보를 수동으로 가리거나 자료를 제외하고 파일 메타데이터를 제거한 뒤, 처리 결과와 공개 범위를 사용자에게 확인받는다. 촬영일은 확인된 값으로 따로 저장하여 원본 메타데이터 제거와 구분한다. 가림·제거 실패 또는 미완료 자료는 차단하며 원본으로 대신 전달하지 않는다. 문제가 없는 다른 자료로 상담을 계속할 수 있다. 전달본 권한으로 원본을 열람할 수 없고, 처리한 자료를 수정하면 이전 확인을 재사용하지 않는다.

종료 시점의 열람 범위는 제공할 수 있는 정보의 상한이다. 자료를 반드시 영구 보존한다는 뜻이 아니며 제6.6~6.7절의 정정·삭제가 우선한다. 삭제되거나 재확인이 필요한 자료는 종료 기사에게도 기존 전달본으로 계속 제공하지 않는다. 같은 기사가 다른 항목의 활성 예약을 가지고 있으면 그 관계의 권한은 유지하되, 이를 종료 항목의 후속 기록이나 다른 상담 열람 권한으로 확대하지 않는다. 한 항목 종료를 이유로 기사 계정 전체의 접근을 일괄 차단하지 않는다.

권한 변경은 앱 조회·사진·원본·PDF 생성·내려받기 API에 적용한다. 외부 공유 링크와 `.md` 파일 다운로드는 제공하지 않는다. 외부 공유용으로 확인한 앱 보고서와 PDF는 같은 자료·공개 범위를 사용하며 생성 시각·미확인 상태를 표시한다. 본인 조회와 확정 기사 인계의 범위는 각 관계의 권한을 따르며 외부 공유 범위와 구분한다. PDF 생성 접수부터 결과 전달까지 근거·가림·권한을 검사하여 생성 중 변경·삭제된 자료의 결과는 제공하지 않는다. 수정·삭제 후 기존 PDF를 최신본으로 재제공하지 않고 새 확인 후 다시 생성한다. 이미 다운로드한 파일을 자동 갱신·회수할 수는 없으며 서비스에 남은 전달본에는 제6.6~6.7절의 갱신·삭제 규칙을 적용한다.

### 6.4 동선 추천의 비교 기준

아래는 원문의 동선 효율 우선 추천을 검증하기 위한 **명세화 규칙**이다.

1. 작업 분야·지역·사용자 가능 조건이 맞고, 예상 작업 시간과 이동 시간을 포함해 기존 일정 사이에 삽입 가능한 작업항목만 우선순위 비교 대상으로 삼는다. 같은 요청의 다른 항목도 독립 후보로 다루되 기사 일정·활성 예약 조건은 함께 검사한다. 사용자 가능 구간과 특정 희망 시각의 의미, 추정·확인 소요 시간의 구분은 제6.2절을 따른다. 견적에서 소요 시간이나 작업 전제가 바뀌면 같은 기준으로 다시 검사한다.
2. 같은 빈 시간의 앞뒤 방문 위치를 A·B, 새 요청 위치를 R이라 할 때 추가 이동 시간은 `이동(A, R) + 이동(R, B) - 이동(A, B)`로 계산한다. 앞뒤 일정이 없는 경우에는 기준 자료에 명시한 출발·복귀 위치를 사용한다. 자료가 없으면 동선 효율을 미산정으로 표시하며 계산된 절감 효과처럼 제시하지 않는다.
3. 적합 후보는 가능한 삽입 구간 중 추가 이동 시간이 가장 작은 값을 기준으로 오름차순 정렬한다. 동률이면 요청 접수 시각, 추천용 식별자 순으로 정렬한다. 동선 효율만 미산정인 후보는 산정 가능한 후보 뒤에서 별도 표시하며, AI가 이동 값을 만들어 순위를 정하지 않는다. 작업·이동 시간 부족으로 충돌 여부까지 검사할 수 없는 요청은 적합 후보로 확정 표시하지 않고 보완을 요청한다.
4. **선택 반영:** 서울 전역의 동 단위 대표 위치와 대표 위치 사이의 고정 모의 이동시간표, 기사별 고정 출발·복귀 위치를 사용한다. 같은 동 안의 이동도 사전에 정한 이동시간을 적용하며 같은 동이라는 이유로 0분을 가정하지 않는다. 상담 전 작업 시간은 공통 기준표에서 가져오며 표에 없으면 제6.2절에 따라 기사 확인으로 보완한다. 확인 전에는 동선 적합·효율을 확정하지 않지만 일반 탐색·상담 선택은 허용한다. 위치·이동·시간 자료의 식별자·버전·적용 가정을 기록하여 계산을 재현한다. 서울 내 필요한 동·이동 구간 누락은 기준 자료 미비로 표시하고 임의 값으로 충돌 검사를 통과시키지 않는다. 실제 도로 이동·도착 시각을 보장하지 않는다.
5. 긴급 요청은 할인 대기를 유도하는 순위 대상으로 처리하지 않고 즉시 대응 경로 안내를 우선한다. 순위는 할인율이나 예약을 확정하지 않으며 최종 시간·금액은 기사 제안과 사용자 선택에 따른다.

### 6.5 사례 점수와 기사 후보 구성

아래는 복수 분야·기사 순위의 **선택 반영** 규칙이다. 동선 순위(제6.4절)와 사례 관련성 순위는 서로 다른 결과이다.

1. 작업항목별로 사용자가 확인한 지원 분야의 합집합과 해당 증상을 사용해 사례를 검색한다. 같은 항목에서 같은 사례 식별자는 한 번만 평가한다. AI는 최초 증상·관찰·작업 내용 등 원본 근거와 함께 관련성 1~5점을 반환한다. 1점은 무관, 2점은 분야만 유사, 3점은 일부 증상·작업이 관련, 4점은 주요 증상·작업이 관련, 5점은 주요 증상·조건·작업 근거가 매우 밀접한 경우이다. 높은 점수도 현재 원인을 확정하지 않는다.
2. 3점 이상인 사례 중 기사별 상위 3개 평균을 사용한다. 1~2개면 있는 사례만 평균하고 0개는 점수 없음이다. 점수 순, 동점 사례는 사례 식별자 순으로 집계 대상을 정한다. 기사 순위는 반올림 전 평균 내림차순, 평균 동률이면 기사 식별자 순으로 재현한다.
3. 작업항목별로 분야·지역·시간 조건과 자기 요청 제외를 적용한 사례 추천 기사 상위 5명을 제공한다. 한 항목의 복수 분야에 걸친 같은 기사는 한 번만 표시하고 일치 분야·미지원 분야·집계 사례·점수·근거를 함께 제공한다. 한 기사가 모든 분야를 해결한다고 단정하지 않는다. 다른 작업항목에도 같은 기사가 후보로 나올 수 있지만 예약·실제 작업의 기사 충돌은 허용하지 않는다. 항목별 활성 예약 하나라는 제6.2절의 제한을 적용한다.
4. 시연 자료·연관 사례가 없는 제품도 분야·지역에 맞는 기사를 별도 일반 후보 목록에서 기사 식별자 순으로 조회·선택할 수 있다. 소요 시간·일정 적합성이 미확인이면 표시하고 기사 확인 후 작업·이동 검사를 거쳐 예약한다. 일반 후보를 사례 상위 5명에 끼워 넣거나 없는 점수·경험을 만들지 않는다. 사례 평가 실패도 `평가 미완료`로 구분하여 일반 탐색을 허용하며 자기 참여 차단은 유지한다.

### 6.6 경과 비교·정정·파생 결과의 유효성

**선택 반영:** 경과 분석은 벽지 물자국을 대상으로 하며 사용자가 동일 부위를 묶는다. 날짜 확인된 사진 2장 이상이면 최초·최신을 기본 선택한다. 같은 날짜의 사진은 사진 식별자로 선택을 재현하되 시간 선후는 미확인으로 표시한다. 날짜 미확인 사진은 별도 묶음에서 조회하고 사용자가 직접 비교 사진으로 선택할 수 있으나 시간에 따른 악화·호전을 단정하지 않는다.

| 출력 | 내용·예외 |
| --- | --- |
| 비교 입력·상태 | 부위 묶음, 서로 다른 두 사진 식별자, 확인된 촬영일 또는 미확인, 비교 가능·불가와 사유, 변화 있음·없음. 자료 부족이면 비교 미수행으로 구분한다. |
| 변화 영역 | 각 사진 식별자·가로/세로 크기와 `[x_min, y_min, x_max, y_max]` 사각형 목록. 표시 방향을 정규화한 사진의 좌상단이 원점이며 0~1 정규 좌표로 `x_min < x_max`, `y_min < y_max`를 만족해야 한다. 각 사각형에 관찰 설명을 연결한다. |
| 변화 설명·원인 | 관찰 가능한 확대·축소·색상 등과 근거를 연결한다. 변화 없음은 빈 사각형 목록, 비교 불가는 영역 단정 없이 사유·재촬영 안내를 제공한다. 원인 미확인은 변화 여부와 독립적으로 표시한다. 실제 면적·내부 원인을 사진만으로 확정하지 않는다. |

**정정과 갱신 순서**

1. 본인 사진·증상·조치·날짜를 정정하면 현재 내용을 덮어쓰고 서버 최종 수정일을 갱신한다. 요약은 수정 초안을 사용자 확인 후 현재 요약에 덮어쓴다. 촬영일·발견일을 수정일로 바꾸지 않는다. 이전 본문·사진을 수정 이력이나 복원본으로 쌓지 않는다.
2. 현재 자료 식별값(증가 번호 또는 동등한 식별값), 선택 비교쌍과 요약 확인 상태를 유지한다. 이것은 이전 내용 보관이 아니라 오래된 분석을 판별하기 위한 값이다. 견적·예약의 합의 조건·버전은 제6.2절에 따라 별도 보존하며 요청 삭제 시 함께 제거한다.
3. 자료 추가·정정·삭제, 비교쌍 변경 시 참조하는 작업항목의 관련 결과에 갱신 필요를 표시한다. AI 재분석·요약 재생성에는 비용이 발생하므로 사용자가 요청할 때만 실행하며 자료 변경·조회만으로 자동 호출하지 않는다. 새 초안은 최신 입력 검사와 사용자 확인 후 반영한다. 직접 최신 내용으로 요약을 정정·확인할 수도 있다. 공개 범위·가림만 바뀌면 관련 전달본·PDF 확인만 무효화하고 원본 분석·요약은 유지한다. 참조하지 않는 항목은 유지한다.
4. AI 결과 수신 시 원본 존재·입력 식별값·권한을 검사하고, 요약 확정·앱의 확정 보고서 조회·전달·PDF 생성과 결과 제공 직전에는 최신 사용자 확인과 해당 목적의 가림·공개 범위도 검사한다. 본인 초안 검토는 사용자 확정 전에도 미확정 상태로 허용하되 삭제 근거를 제공하거나 초안을 전달본으로 취급하지 않는다. 생성 중 근거가 변경·삭제되거나 권한이 바뀌면 해당 결과를 확정·전달하지 않는다. 실행 도중 입력이 바뀐 AI 결과는 오래된 결과로 표시하고 현재 요약을 덮어쓰지 않는다. 재시도 결과도 동일하며 이미 삭제된 자료나 요청의 결과를 되살리지 않는다.
5. 서비스에 남은 오래된 전달본과 PDF는 새 열람·다운로드에서 제외한다. 완료·중단 시점 전달본에도 근거 정정·삭제가 적용된다. 종료 기사에게 해당 항목의 새 후속 기록을 공개하지 않으며 기존 허용 범위에서 정정한 종료본만 재확인 후 제공한다. 다른 항목의 활성 관계는 그 범위 안에서 유지한다. 정정 이력으로 이전 전달본을 보관하지 않는다. 이미 외부로 내려받은 파일은 회수 대상이 아니며 수정 후 새 파일을 전달한다.

### 6.7 보관과 개별 삭제

**선택 반영:** 서비스 자료는 팀이 삭제할 때까지 보관한다. 종료·취소만으로 자동 삭제하지 않는다. 본인 사진·기록·요청의 개별 삭제 API는 대상 식별자와 삭제 범위를 받아 성공·거절·처리 중·실패 및 사유를 조회할 수 있게 한다.

| 조건·대상 | 처리 규칙 |
| --- | --- |
| 소유 검사 | 요청 소유 사용자만 본인 요청 사진·기록을 삭제한다. 사용자 본인 사진은 대기·수락·진행 중 상담이나 확정·작업 중·중단 요청 예약이 있어도 삭제할 수 있다. 요청 소유를 이유로 기사 작성 수행 기록을 개별 삭제할 권한은 부여하지 않는다. 기사 업로드 사진은 본인 프로필에 속하며 이 요청 삭제 API의 대상이 아니다. |
| 본인 사진 삭제 | 원본·파일·파생 전달본·참조를 제거하고 해당 사진을 사용하는 모든 작업항목의 분석·요약·인계·PDF를 재확인 필요로 바꾼다. 삭제 근거가 담긴 출력·전달본은 더 이상 제공하지 않는다. 상담·예약·작업과 합의 조건은 유지하며 남은 근거로 재생성·수동 정정·사용자 확인 전에는 관련 결과를 확정·공유하지 않는다. |
| 마지막 사진·사진 한도 | 마지막 본인 사진도 삭제할 수 있다. 요청·활성 예약은 유지하며 사진이 없는 분석은 자료 부족으로 처리한다. 남은 텍스트 사실로 수동 요약을 정정·확인할 수 있지만 삭제한 사진을 관찰 근거로 계속 인용하지 않는다. 요청 전체 저장 한도는 모든 항목에서 사용자가 올린 접수·상담 보완·경과·조치 결과 사진을 합쳐 30장이며 삭제 완료 사진 수만큼 한도를 회복한다. 기사 프로필 사진은 합산하지 않는다. |
| 본인 일반 기록 개별 삭제 | 사진 이외의 기록은 관련 활성 상담·예약·작업이 없을 때 허용한다. 반영 직전에 소유와 이를 사용하는 작업항목의 활성 관계를 모두 재검사하고 동시 관계 생성과 함께 일관되게 처리한다. 허용되면 해당 원본·파생 전달본·참조를 정리하고 관련 결과를 재확인 필요로 바꾼다. |
| 요청 전체 삭제의 활성 검사 | 어느 작업항목이든 상담이 대기·수락·진행 중이거나 예약이 확정·작업 중·중단 요청이면 전체 삭제를 거절한다. 다른 항목의 관계가 남았는데 한 예약의 취소·완료·중단만으로 삭제를 허용하지 않는다. 필요한 종료 절차를 안내하고 상담·예약을 자동 취소하지 않는다. |
| 요청 전체 삭제 | 활성 관계가 없는 최초 접수 또는 모든 작업항목의 관계가 정리된 요청에서 허용한다. 요청에 연결된 항목·원본·파일·전달본·분석·문답·상담·견적·예약·작업·PDF를 함께 정리한다. 기사 프로필과 그 포트폴리오·사례 사진, 다른 요청·별도 평가 자료는 삭제하지 않는다. 삭제 뒤 해당 요청 자료는 양측 과거 URL·식별자로 조회·내려받기·수정할 수 없다. |
| 사진 삭제와 동시 처리 | 반영 직전에 소유를 재검사하고 삭제 대상과 참조 결과에 대한 새 열람·전달·생성 결과 반영을 차단한다. 새 상담·예약이 먼저 생성되었어도 본인 사진 삭제는 허용한다. 예약 확정과 사진 삭제는 각 상태를 일치시켜 반영하며 삭제 사진이 다시 인계되지 않아야 한다. 삭제와 무관한 자료·항목·관계는 계속 사용할 수 있다. |
| 전체 삭제와 동시 처리 | 반영 직전에 소유·모든 항목의 활성 관계를 재검사한다. 전체 삭제 중에는 새 항목·상담·예약·AI 작업·자료 전달을 막는다. 활성 관계 생성이 먼저 반영되면 전체 삭제를 거절하고, 전체 삭제가 먼저이면 관계 생성을 거절한다. 사진·전체 삭제 모두 늦은 AI·PDF 결과나 반복 삭제로 자료가 복원되지 않는다. |
| 부분 정리 실패 | 파일 또는 연결 자료 일부 제거가 실패하면 삭제 미완료로 표시하고 삭제 대상·관련 결과의 접근 차단을 유지한다. 사진 일부 삭제 실패로 다른 활성 예약을 종료하지 않는다. 재시도는 남은 정리를 이어서 수행하며 전체 정리가 확인된 뒤에만 해당 삭제를 완료로 표시한다. 삭제 상태 추적에 필요한 식별자·처리 결과 외에 삭제 본문·파일을 이력으로 남기지 않는다. |

별도로 구성한 비식별 평가 자료와 실행 기록은 최종 평가 검증까지 보존한다. 서비스 접수자료를 복제하여 보존 예외를 만들지 않는다. 외부 수신자가 이미 다운로드한 파일의 회수는 보장하지 않으며 서비스 내 복사본은 삭제 범위에 포함한다.

### 6.8 AI 작업·실패 복귀·검증된 안내

아래는 AI 처리와 문답·안내의 **선택 반영** 규칙이다.

| 항목 | 입력·출력·예외 |
| --- | --- |
| 작업 접수·조회 | 증상 정리·질문·추천 설명·경과 분석·인계 초안 등 AI 처리마다 AI 작업 식별자, 대상 요청·작업항목과 입력 자료 식별값을 연결한다. 접수 응답으로 식별자·대기 상태·접수 시각을 제공하고 권한 있는 조회로 상태·결과·오류를 반환한다. 상태 조회는 새 작업을 만들지 않는다. |
| 전체 제한시간 | 서버 접수 시각부터 대기·처리·재시도·결과 저장을 포함하여 60초이다. 60초에 도달하면 시간 초과로 종결하며 늦은 응답을 성공으로 바꾸거나 사용자 요약을 갱신하지 않는다. 자동 재시도로 접수 시각·마감 시각을 초기화하지 않는다. |
| 자동 재시도 | 사전 정의한 일시적 연결 오류·일시적 서비스 장애·요청 제한에만 남은 시간 안에서 최대 1회 수행한다. 인증·입력 오류, 판단 유보·비교 불가·미지원, 근거·출력 검증 실패는 자동 재시도 대상이 아니다. 재시도 횟수·오류·시각을 결과와 연결한다. |
| AI 미선택·수동 복귀 | AI를 선택하지 않으면 작업을 생성하지 않고 사용자가 직접 분야·요약을 확인하여 상담 선택·견적·예약으로 진행한다. AI 미선택은 실패·시간 초과와 구분한다. 실패·시간 초과 시 남은 저장 입력을 보존하고 AI 분석 미완료로 표시한다. 사용자가 직접 확인한 항목별 분야·요약과 전달 가능한 자료로 상담을 진행할 수 있다. 본인 사진을 모두 삭제한 경우 사진 근거 없이 확인 가능한 텍스트를 사용하며 삭제 근거를 복원하지 않는다. 수동 재시도는 새 작업 식별자로 구분하되 실패를 지우거나 요청당 문답 한도를 초기화하지 않는다. |
| 문답 종료 | 요청당 질문 최대 5회이며 답변·건너뛰기를 저장한다. 필요한 정보가 충분하거나 사용자가 진행을 선택하면 더 묻지 않고 확인 단계로 간다. 미확인 항목을 꾸며 채우지 않으며 긴급 안내를 문답 완료에 묶지 않는다. |
| 긴급 분기 | 사용자 긴급 표시와 사전 정의·버전 관리한 구조화 문답 답변을 기준으로 분기한다. 검증된 정적 안내·공식 경로와 공개 기사 연락수단을 우선 제공하며 AI 성공·로그인·일정·견적·예약을 요구하지 않는다. 실제 방문 가능 여부는 당사자가 확인하며 임의 연락처·방문 가능 일정을 생성하지 않는다. |
| 가이드·공식 경로 | 적용 조건·단계·주의·용품·금지·중단 기준과 공식 경로의 출처·확인일·버전을 사전 등록한다. AI는 고정 내용의 의미를 보존한 설명만 맞춤화한다. 검증 실패·등록 자료 없음·적용 불가이면 생성 절차를 전달하지 않고 검증된 대체 경로 또는 안내 불가를 표시한다. 자료 갱신 시 영향받는 가이드·평가를 다시 검증한다. |

AI 성공 상태는 사용자 확정 상태가 아니다. 결과 저장·확정·전달에는 제6.6절의 최신 자료 검사와 제6.3절의 공개 범위 검사를 적용한다. 긴급 대응 경로는 지원 범위 밖·AI 실패·기사 부재에서도 유지한다.

**근거:** 기획서 제4.1절, 제5.1절, 제5.3절, 제6.2절, 제6.4절, 제7.2절, 제7.3절. 이 절은 서비스의 일반 사용자 화면 기능과 구분되는 프로젝트 검증 요구사항이다.

### 8.1 평가 절차

1. 제8.3절에 따라 자료의 출처·활용 가능 여부·개인 식별 정보 부재를 확인하고, 접수 증상·사진, 수리 사례, 기사 전문 분야·지역·기존 일정, 사용자 가능 기간, 작업·비용 조건을 기준 시나리오로 구성한다.
2. **선택 반영:** 제8.2절의 8개 평가군별 최소 10개 기준 사례를 각각 3회 실행한다. 평가 입력·정답·루브릭·제8.4절의 목표값과 표본 선정 기준은 출력 생성 전에 고정하고 버전을 기록한다. 각 사례는 필요한 AI 결과 또는 정상 오류·차단 응답 중 무엇을 기대하는지 명시한다. 최소 80개 평가군별 사례·240건의 실행 결과이며 가장 유리한 출력만 선택하지 않는다.
3. **선택 반영:** 생성기와 평가기는 같은 모델을 사용하되 역할·대화 맥락을 분리한다. 평가기에는 원본 입력·서비스 출력·정답·루브릭을 제공하며 생성기의 대화 맥락을 재사용하지 않는다. 동일 모델 사용을 독립된 외부 검증으로 과장하지 않고 규칙 검사·사람 검토를 병행한다.
4. **명세화:** 평가 실행마다 실행 식별자를 부여하고 아래 실행 조건을 연결한다. 동일 조건의 반복 결과는 회차별로 보존하며 유리한 출력만 선택해 집계하지 않는다.
5. 사용자·기사 역할의 평가와 별도의 품질 평가를 통해 정보 충분성, AI 추가 질문·확인사항의 적절성, 근거 일치도를 확인한다. 추가 질문·확인사항은 사용자가 입력한 사진·증상·답변을 바탕으로 서비스 AI가 생성한 내용을 뜻한다. **선택 반영:** AI 품질은 사용자가 확인·수정하기 전의 서비스 생성 출력을 대상으로 하며 사용자 수정본은 품질 점수를 대체하지 않는다. 자가 해결 안내는 구성요소의 존재뿐 아니라 검증된 원문의 적용 조건·단계·금지 조건·중단 기준과 대조한다.
6. 날짜·시간·지역·금액은 AI 채점과 함께 규칙 기반 검사를 수행한다. 시간 검사는 기준 시각, 신규 확정·시작 전 변경의 최소 준비시간, 조기 시작 동의, 진행 중 변경 합의, 예상·확인 소요 시간, 작업·이동 점유 및 사용자 시간 중복 확인을 포함한다. 필수 기능 규칙의 통과 여부와 AI 출력의 품질 점수는 별도로 기록한다.
7. **선택 반영:** 사람은 평가군별 실행 결과의 20%(소수 건수 올림), 최소 5건을 원본과 대조한다. 10개 사례×3회이면 평가군별 최소 6건이다. 표본은 회차와 해당 군에 존재하는 통과·실패·보류를 포함하도록 선정하며, 무출력 실패는 입력·작업 상태·오류 기록으로 확인한다. 치명 실패 의심·이견 건은 표본 외에도 모두 추가 검토한다. 원판정·검토자·근거·최종 판정·수정 사유를 기록하고 미해결 이견은 평가 보류로 남긴다.
8. 항목별 점수, 판정 근거, 정보 누락·오류, 전체 평가 건수, 비교 불가·평가 보류 건수 및 사람의 검토 결과를 기록하고 제8.4절에 따라 완료 여부를 판정한다.

| 실행 기록 | 필수 내용 |
| --- | --- |
| 실행·자료 식별 | 실행 식별자, 실행 시각, 시나리오 식별자, 데이터셋·정답·루브릭·검색 자료 버전 |
| 생성기·평가기 조건 | 역할별 모델 식별자와 확인 가능한 버전, 프롬프트 원문 또는 저장 위치·버전, 출력에 영향을 주는 설정값. 제공되지 않는 버전·설정은 확인 불가로 기록한다. |
| 반복·집계 | 사전 확정 반복 횟수, 회차별 입력·사용자 수정 전 출력·판정, 기대 결과 유형, 무출력 실패·보류·재시도 내역, 집계 단위와 방식 |
| 사람의 검토 | 표본 선정 기준과 대상, 검토자, 원판정과 최종 판정, 이견·치명 실패 검토 근거와 처리 결과 |

실행 조건이 달라진 결과는 변경 항목을 밝히고 구분해 비교한다. 기준·모델·프롬프트·검색 자료를 바꾼 뒤에는 영향을 받는 시나리오를 다시 평가한다. 규칙 기반 검사와 사람의 검토도 같은 실행 식별자에 연결하여 원래 출력과 최종 판정을 추적할 수 있어야 한다.

### 8.2 평가 대상과 자료

아래 8개 행을 각각 하나의 평가군으로 삼는다. 각 군에 최소 10개 기준 사례와 정상·예외·경계 입력을 포함한다. 같은 원자료를 여러 군에서 쓰더라도 군별 정답·실행·집계를 구분한다. 가이드·사진의 주입 오류 출력은 평가 절차 검증용 추가 자료이며 최소 사례 수·서비스 생성 품질 분모에 대신 넣지 않는다.

| 평가 대상 | 주요 지표 | 필요한 기준 자료 |
| --- | --- | --- |
| 증상 요약·분야 분류 | 분야 일치율, 필수 정보 포함률, 근거 없는 정보 포함 비율 | 원본 증상, 기준 분야, 필수 정보, 허용 추정 범위 |
| 자가 해결 가이드 | 가이드 원문 일치율, 적용 불가 안내 차단, 필수 중단 기준 준수, 치명 실패 건수 | 검증된 원문과 허용 절차, 적용 가능·불가 입력, 필수 주의·금지·중단 조건, 구성요소는 있으나 내용이 충돌하는 오류 출력 |
| 긴급·분석 실패 경로 | 긴급 대응 안내 접근 여부, 잘못된 선행 조건·방문 가능성 단정 건수 | 사용자 긴급 표시·사전 정의 입력, AI 오류·판단 유보·적합 기사 없음의 결합 사례, 검증된 정적 대응 안내 |
| 사례 기반 기사 추천 | 추천 관련성, 추천 근거 일치도, 기본 조건 충족률 | 연관·무관 사례, 실제/모의 라벨, 기사 분야·지역·시간 |
| 일정·할인 예약 | 일정·지역 조건 충족률, 일정 충돌 건수, 금액 조건 일관성 | 작업항목별 예약·동일 항목 경쟁 제안, 동일 기사 충돌·다른 기사 방문의 사용자 중복 확인, 조기 시작·진행 중 변경 합의, 서울 전역의 동 단위 이동 자료, 동일 작업·비용 조건의 즉시 예약 가능·충돌·인근 일정 연계·동률·미산정 사례, 추천 추정·기사 확인 소요 시간과 준비시간 경계 |
| 사진·경과 분석 | 기준 사진쌍 판정 일치율, 변화 영역·설명 정확성, 근거 연결 정확성, 판단 유보 적절성 | 변화 있음·없음·비교 불가 사진쌍과 증상 기록, 사진쌍별 허용 변화 영역·관찰 설명 및 필수 출력 항목 |

AI 추가 질문·확인사항 평가군은 FR-AI-02의 서비스 생성 출력을 대상으로 한다. 사용자·기사 간 질문·사진 보완 요청은 외부 연락으로 진행하며 앱 대화 저장·AI 품질 평가 대상이 아니다. 사용자 보완 자료와 기사 방문 준비사항의 등록·조회는 FR-CON-03·FR-HND-05와 관련 AC로 확인한다.

자가 해결 가이드는 **원문과 일치하는 안내와 적용 불가 입력에서의 안내 차단을 함께 평가**한다. **명세화:** 원문별 적용 조건·허용 단계·필수 주의사항·금지 조건·즉시 중단 기준을 평가 전에 정하고 생성된 결과의 해당 내용과 대조한다. 금지된 작업 안내, 적용 금지 조건의 반전, 필수 중단 조건의 누락·반전은 치명 실패로 기록한다. 제목과 항목이 모두 있거나 다른 문장이 정확하다는 이유로 이를 통과 처리하지 않는다. 오류 출력을 넣어 평가 절차가 이를 실제 실패로 판정하는지도 확인한다.

긴급 안내 접근, 작업항목별 상담·견적·예약·작업 상태 전이, 전체 요청 종료, 진행 중 사진 삭제, 앱·PDF 전달본 접근 통제는 AI 점수만으로 검증하지 않는다. 제7장의 경계·동시 요청·가림 실패 사례를 시스템 동작으로 확인하고, 조건을 만족한 정상 경로와 함께 결과를 기록한다.

가이드·사진 분석의 오류 검수를 위해 별도로 주입한 출력은 평가 절차 검증용으로 표시하고 서비스가 생성한 출력의 품질 점수 분모와 치명 실패 건수에 섞지 않는다. 주입 오류를 기대한 실패 유형으로 판정하면 해당 평가 절차 검수는 통과한다. 주입 오류를 놓치면 해당 평가 절차 검수를 실패로 기록하고 보완 후 다시 확인한다.

사진 변화 분석은 **변화 유무 판정, 변화 영역·설명의 정확성, 사진 근거 연결을 구분해 평가**한다. **명세화:** 평가 전에 기준 사진쌍별로 관찰 가능한 변화 위치·범위·방향과 면적·색상의 허용 설명, 필수 출력 항목 및 영역 표시의 허용 범위를 정한다. 면적은 사진에서 확인할 수 있는 확대·축소 등의 설명으로 평가할 수 있으며, 실제 면적의 정밀 측정을 요구하지 않는다. 변화가 없는 사진쌍은 변화 없음 표시와 허위 영역·설명 부재를 확인하고, 비교 불가 사진쌍은 판단 유보·재촬영 안내를 검증한다. **선택 반영:** 세 유형을 포함하되 평가군 전체 최소 10개 사례·3회 반복과 제8.4절의 전체 합산 기준을 유지하며 유형별 최소 수량·별도 합격선은 추가하지 않는다.

일정·할인 예약은 **동일한 작업 범위와 비용 조건을 유지한 기준 시나리오**에서 평가한다. **명세화:** 작업 종류·수량·예상 소요 시간, 할인 전 비용 항목과 추가 비용 조건을 고정하고, 방문 가능 기간·기존 일정·이동 부담 등 비교하려는 조건과 기사 할인 제안만 구분해 기록한다. 작업 범위 축소나 부품비 제외로 낮아진 금액을 동선 연계 할인 효과로 계산하지 않는다.

이동 시간 비교는 동일한 가정 아래 계산한 시뮬레이션 값으로 수행한다. 동선 우선순위 검증에는 지역·분야·시간 조건을 모두 충족하지만 이동 부담이 다른 요청을 함께 배치하고, 사전에 정한 효율 기준에 따른 추천 순서를 확인한다. 모의평가 결과는 통제된 시나리오의 출력 품질과 조건 충족도를 나타내며, 실제 현장의 비용 절감액·수리 만족도·이동 시간 절감 효과를 입증한 값으로 사용하지 않는다.

### 8.3 평가 자료의 출처와 사용 조건

**선택 반영:** 평가 데이터셋은 사전 확인된 수리·제품 안내 자료, 별도로 준비한 모의 사례·재현 사진, 기준 시나리오와 모의 기사 프로필·일정으로 구성한다. 실제 접수자료를 공개·별도 AI 자료로 전환하지 않는다. 모든 안내·사진·일정·정답 근거의 출처·사용 가능 여부를 기록한다.

| 자료 구분 | 확인·기록할 내용 | 사용 조건 |
| --- | --- | --- |
| 수리·제품 안내 자료 | 원자료 위치, 제공자, 확인일·버전, 사용 범위 | 출처와 활용 가능 여부가 확인된 자료만 가이드·정답 근거로 사용한다. |

**명세화:** 출처·사용 조건·확인 결과와 식별 정보 제거 결과를 평가 자료 목록에 기록한다. 실제 개인 식별 정보가 남았거나 자료 사용 가능 여부가 확인되지 않으면 평가 입력에서 제외한다. 제외·교체 내역은 데이터셋 버전에 남기고, 비식별 평가 자료·실행 기록은 최종 검증까지 보존한다. 이는 서비스 본문 수정 이력 보관이나 실제 접수자료 복제의 근거가 아니다.

### 8.4 지표 정의와 완료 판정

집계 방식은 **명세화**, 아래 수치와 동일 모델·반복·표본 기준은 **선택 반영**이다. 필수 항목·허용 답안·루브릭은 출력 생성 전에 고정한다. 분자·분모·보류를 함께 보고하고 분모가 0이면 `산출 불가`이며 합격으로 표시하지 않는다. 각 평가군의 해당 지표를 3회 전체 합산하여 판정하고 회차별 결과도 제시한다. 다른 평가군의 높은 점수로 미달 항목을 상쇄하지 않는다.

| 일정 충돌·정보 누락·왜곡 건수 | 기준 시나리오별 발생 여부와 위반 항목을 전체 건수와 함께 집계한다. 동일 기사 일정 충돌·사용자 확인 없는 방문 중복과, 다른 기사의 방문을 최신 사용자 확인으로 허용한 중복을 구분한다. 잘못된 확정·변경으로 만든 충돌과 실제 작업 초과로 드러난 후속 충돌도 분리한다. 후자는 충돌 표시·신규 확정 차단·재검사를 검수하며 사실을 숨기거나 기존 예약을 자동 변경하면 실패이다. 하나의 출력에 여러 오류가 있으면 출력 건수와 오류 항목 수를 구분한다. |

**무출력과 정상 오류 응답의 판정**

- AI 결과를 요구한 사례에서 처리 오류·시간 초과·검증 차단으로 필요한 결과가 없으면 해당 실행을 `사례 실패`로 기록한다. 평가 대상에서 제외하거나 `평가 보류`로 바꾸지 않는다. 출력 일부만 없을 때도 그 필수 항목을 누락 실패로 센다.
- 정답 자료에는 실행별 필수 출력과 지표별 평가 단위·개수를 미리 정의한다. 무출력의 성공률·일치율은 해당 단위를 분모에 포함하고 성공 수는 0으로 센다. 필수 정보·근거 항목도 같은 방식으로 포함하며 5점 척도 지표는 1점으로 집계한다.
- 사실 주장이나 질문 자체가 없어 근거 없는 정보 비율·반복 질문 비율을 계산할 수 없으면 `산출 불가`와 사례 실패를 함께 기록한다. 이를 오류 0% 또는 좋은 품질로 처리하지 않는다. 판정 가능한 다른 필수 지표의 실패와 누락 내역을 유지한다.
- 적용 불가 안내, 정상적인 후보 없음, 사진 비교 불가, 의도적으로 발생시킨 장애의 오류 응답·수동 복귀처럼 정상 예외 응답이 정답인 사례는 사전에 정한 기대 결과로 판정한다. AI 결과를 요구했던 사례의 정답을 실행 후 오류 응답으로 바꾸지 않는다.
- 생성된 결과가 검증 과정에서 차단됐다면 차단 전 출력과 사유도 보존하여 치명 실패·내용 오류를 평가한다. 사용자에게 전달하지 않았다는 이유로 생성 품질의 실패를 없애지 않으며, 잘못된 결과의 전달을 차단한 기능 검수는 별도로 판정한다.

**반복 실행·사람 검토의 집계**

- 반복 횟수와 시나리오별·회차별 집계 단위는 실행 전에 고정한다. 각 회차의 결과와 전체 합계를 함께 제시하고, 재시도 전 실패·보류를 삭제하거나 가장 좋은 회차만 대표 결과로 선택하지 않는다. 자동 재시도는 동일 AI 작업의 60초 안에서 수행하며 개별 시도 오류를 보존한다. 실패로 종료된 작업의 수동 재시도는 별도 실행으로 기록하고 원래 3회 평가의 실패를 성공으로 교체하지 않는다.
- 사람의 표본 검토 건수, 원판정과의 일치·불일치 건수, 이견 해결·미해결 건수를 구분한다. 최종 집계에는 검토 후 판정을 쓰되 원판정과 변경 근거를 보존한다. 표본에서 발견된 동일 유형의 오판은 영향 범위를 확인하고 해당 결과를 다시 검토한다.
- 규칙 위반과 가이드 치명 실패는 반복 평균으로 상쇄하지 않는다. 수정 후 재평가 결과는 별도 실행으로 기록하고 이전 실패 이력도 유지한다.

**평가 보류·비교 불가 처리**

- 판단 근거가 부족해 채점할 수 없는 출력은 `평가 보류`로 기록하고 사유를 남긴다. 필요한 결과의 무출력은 앞서 정의한 사례 실패이며 보류에 포함하지 않는다. 지표별 전체 대상 수, 판정 가능 수, 무출력 실패 수, 보류 수와 보류 비율을 함께 제시한다. 보류 건을 성공 건으로 계산하거나 보고에서 숨기지 않는다.
- 사진쌍의 `비교 불가`는 정상적인 정답 분류가 될 수 있다. 기준상 비교 불가인 사진쌍에 대해 판단을 유보하고 재촬영을 안내했는지는 판정 일치율과 유보 적절성 평가에 포함한다. 사진 비교 불가와 평가자의 채점 보류를 구분한다.
- 변화 영역·설명 정확성의 평가 대상 여부는 서비스 출력이 아닌 사전 정답 기준으로 정한다. 기준상 비교 가능한 사진쌍에 서비스가 비교 불가를 출력하거나 필수 결과를 누락하면 정확성 실패로 기록하며 평가 대상에서 제외하지 않는다. 기준상 비교 불가인 사진쌍은 해당 정확성 지표에서 제외한 건수를 별도 보고하고, 변화를 단정한 출력은 사진쌍 판정·판단 유보 평가에 반영한다.
- 기준이나 자료가 바뀌면 버전과 변경 사유를 기록하고 영향을 받는 항목을 다시 평가한다. 서로 다른 기준의 점수를 설명 없이 합산하지 않는다.

**완료 판정**

1. 시연 제외로 표시한 FR-INF-03을 제외한 각 FR, 제6장 규칙과 대응 AC를 확인한다. 제외 기능의 구현을 합격 의무로 남기지 않고 범위 일치·전환 차단을 확인한다. 접근 통제·공개 범위·일정·유효한 전이·최신 근거·긴급 안내의 필수 위반은 품질 평균으로 상쇄하지 않는다.
2. AI 품질은 사용자 수정 전 출력에 이 절의 수치와 보류 범위를 적용한다. 규모·3회 반복·사람 표본을 충족해야 하며 필요한 결과의 무출력은 사례 실패로 집계한다. 실패·시간 초과·차단된 오류 출력과 재시도 전 기록을 숨기지 않는다. 일반 API 성능은 후속 별도 검수로 남기며 해당 성능의 합격을 선언하지 않는다. 이 미정 상태는 충족한 기능·AI 품질 검수의 완료를 막지 않는다.
3. 자가 해결 가이드의 치명 실패가 있으면 해당 품질 검수를 실패로 판정한다. 수정 후 영향 범위를 재평가해 치명 실패가 없고 나머지 품질 기준도 충족한 별도 결과를 남기기 전에는 완료로 바꾸지 않는다.
4. 기능 검수·품질·보류·오류·이견·사람 검토 결과를 같은 실행 식별자와 기준 버전에 연결한다. 필수 기능·AI 품질 검수의 미실행·합격 기준 미달·기준 미정 또는 필수 기록·표본 누락은 해당 검수를 미완료로 기록한다. 일반 API 성능의 후속 검수 상태는 별도 항목으로 표시하며 AI 60초 제한은 필수 기능 검수에 유지한다. 이 문서의 확인 기준 작성만으로 실제 기능·모델 평가를 통과한 것으로 표시하지 않는다.
