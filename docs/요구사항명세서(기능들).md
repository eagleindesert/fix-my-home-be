## 1. 적용 기준과 구현 범위

### 1.1 명세 작성 기준

- 본문의 `FR`은 기능 요구사항, `AC`는 기능 확인 시나리오의 식별자이다.
- 제4장의 기능은 이번 프로젝트의 구현 대상으로 작성한다. 특히 **사례 기반 기사 매칭, 동선 연계 할인 예약, 고장 경과 분석 및 사전 인계**는 모두 필수 구현 범위이다.
- 각 기능 묶음의 **근거**는 기준 문서의 절 번호를 가리킨다. 시장 규모, 경쟁 서비스의 기능, 수익 예시는 서비스 요구사항으로 옮기지 않는다.
- 원문 기능을 실제 동작으로 연결하기 위해 도출한 처리 규칙에는 **명세화**를 표시한다. 상태 명칭과 예외 처리 등 원문에 직접 명시되지 않은 내용을 구분하기 위한 표기이다.
- 원문에서 확정하지 않은 사항 중 기능 연결에 필요한 처리·공개 규칙은 **명세화**로 구체화한다. 추가 결정이 필요한 수치·구현 방식은 제9장에 담당 역할과 확정 시점을 정리하며, 미정인 항목을 검증 완료로 처리하지 않는다.

### 1.2 이번 프로젝트의 구현 범위

| 구분 | 포함 기능 및 범위 |
| --- | --- |
| 기본 접수·분석 | 사진·증상 접수, 추가 기록, AI 문답, 증상 요약·분야 후보, 사용자 확인·수정 |
| 해결 경로 | 자가 해결 안내, 제조사 공식 AS 안내, 수리기사 연결, 긴급 요청 우선 안내 |
| 기사 연결·예약 | 기사 프로필·사례 탐색, 상담, 견적 비교, 예약 확정·조회·변경·취소 |
| 핵심 기능 1 | 실제 해결 사례 검색, 담당 기사 연결, 추천 근거 제공, 지역·분야·시간 조건 반영 |
| 핵심 기능 2 | 고정 시각 또는 유연한 방문 기간 등록, 인근 일정·빈 시간 연계, 기사 자율 할인 제안 |
| 핵심 기능 3 | 날짜별 기록, 사진 변화 분석, 근거가 연결된 경과 요약, 사용자 검토, 공유 및 방문 전 인계 |
| 기사 업무 | 요청 수락·거절, 추가 질문·사진 요청, 일정 관리, 방문 준비사항, 작업 완료 및 사례 기록 |
| 정보 관리 | 선택한 상대에게 필요한 정보 전달, 단계별 공개 범위 통제, 별도 활용 동의 및 비식별화 |
| 프로젝트 검증 | 기준 사례·모의 일정·평가 사진을 이용한 AI 에이전트 모의평가 및 규칙 검사 |

사진 변화 분석은 **벽지 물자국 등 선정된 한 가지 문제 유형**을 중심으로 전체 흐름을 구현한다. 모든 가전·설비에 대한 변화 분석을 구현한다는 의미는 아니다. 사례 매칭과 할인 예약은 구축된 기준 사례, 기사 프로필, 모의 일정으로 작동 여부를 검증한다.

### 1.3 이번 명세의 구현 범위에 포함하지 않는 항목

| 항목 | 구분 이유 |
| --- | --- |
| 플랫폼 내 실결제, 수수료 부과·정산 | 기획서 제7.1절에서 사업화 단계의 구체화 대상으로 분리한다. |
| 부품·도구 커머스, 폐기·교체 제휴, B2B 외부 시스템 연동 | 기획서 제7.1절의 향후 확장 범위이다. |
| 업체 구독·광고, 유료 노출, 자격 인증 배지 | 기획서 제8장의 사업화 모델이며 이번 구현 기능으로 확정되어 있지 않다. |
| 영상·음성·오류 코드 입력, 예방 관리, 이사 관리, B2B 시설관리 | 기획서 제9장의 확장 방향이다. |
| 리뷰·평점, 관리자 콘솔, 푸시·문자 알림 | 경쟁 서비스 설명과 별개로 고쳐야집의 이번 구현 요구사항에 명시되지 않았다. |

## 2. 이용 주체와 용어

### 2.1 이용 주체

| 주체 | 역할 |
| --- | --- |
| 사용자 | 문제 접수, 분석 결과 검토, 해결 경로 선택, 기사 선택, 견적·예약 관리, 기록 공유를 수행한다. 임차인을 포함한다. |
| 기사·업체 | 프로필·사례·일정을 관리하고, 요청 검토, 상담, 견적 제안, 방문 준비, 작업 완료 기록을 수행한다. 이하 기능 설명에서는 ‘기사’로 통칭한다. |
| AI | 입력 정리, 추가 질문, 원인·분야 후보, 사례 관련성 설명, 경과 분석·요약을 지원한다. |
| 시스템 | 요청·기록을 저장하고, 등록 데이터에 따른 조건 검사, 예약 처리, 공개 범위 통제를 수행한다. |
| 임대인·관리사무소 | 사용자가 공유하기로 한 경과 요약을 전달받는 외부 수신자이다. 별도 회원 기능이나 수리 승인 권한은 이번 명세에서 요구하지 않는다. |

### 2.2 주요 용어

| 용어 | 정의 |
| --- | --- |
| 요청 | 하나의 고장 문제에 대한 사진, 증상, 문답, 상담, 예약, 조치 결과를 연결하는 접수 단위 |
| 경과 기록 | 해당 문제의 사진, 촬영 날짜, 발생 조건, 시도한 조치와 결과를 시간순으로 정리한 기록 |
| 실제 수리 사례 | 현장 작업에서 얻은 최초 증상, 확인된 원인, 작업 내용, 부품, 전후 사진 등을 구분한 기록 |
| 모의 사례 | 시연·평가를 위해 구성한 사례로, 실제 작업 실적과 구분하여 표시하는 데이터 |
| 견적 제안 | 기사가 제시한 작업 범위, 비용 항목·조건, 구체적인 방문 시간 및 할인 조건 |
| 인계서 | 사용자 확인을 거친 증상·경과·사진 근거·미확인 사항을 기사 방문 준비에 활용하도록 정리한 기록 |
| 확정 정보 | 사용자가 확인한 입력·요약, 기사가 등록한 견적, 시스템에서 확정한 예약 등 해당 주체의 확인을 거친 정보. AI가 실제 고장 원인을 확정했다는 뜻은 아니다. |

## 3. 주요 이용 흐름

### 3.1 사용자 흐름

1. 사진과 증상을 하나의 요청으로 접수한다.
2. AI 추가 질문에 답하고 증상 요약·수리 분야를 확인·수정한다.
3. 상황에 맞는 자가 해결, 제조사 AS, 기사 연결 경로를 선택한다.
4. 기사 연결 전에 작업 지역과 방문 가능 조건을 등록한다. 유사 사례·추천 근거를 확인하며, 동선 제안 탐색을 선택한 경우에는 최소 요청 정보를 보고 상담 참여 의사를 표시한 기사도 비교하여 상담 상대를 선택한다.
5. 기사와 추가 정보를 확인하고 작업 범위·방문 시간·금액 조건을 비교한다.
6. 상세 주소·방문 연락처를 입력·확인하고, 유효한 최신 제안을 선택하여 예약을 확정한다. 상세 방문 정보는 확정 전까지 기사에게 공개하지 않는다.
7. 최신 경과와 인계서를 확인하고 확정 기사에게 필요한 방문 정보를 전달한다.
8. 작업 완료 내역과 이후 참고할 수리 기록을 조회한다.

자가 해결로 문제가 해결되면 결과를 기록하고 요청을 종료한다. 해결되지 않으면 같은 요청의 사진·문답·조치 기록을 유지한 채 기사 연결로 진행한다. 과거 사진이 없어도 최초 사진 한 장과 문답으로 상담·예약 및 인계서 생성을 진행할 수 있다. 긴급 대응이 필요한 경우에는 할인 예약보다 즉시 방문 가능한 경로 안내를 우선한다.

### 3.2 기사 흐름

1. 전문 분야, 활동 지역, 포트폴리오·수리 사례, 방문 가능 일정을 등록한다.
2. 동선 추천에서는 최소 요청 정보만 확인하고 상담 참여 의사를 표시한다. 사용자가 상담 상대로 선택한 후에 사진·요약을 열람하고 상담 요청을 수락·거절하거나 추가 정보를 요청한다.
3. 작업 범위, 세부 비용, 방문 시간과 필요한 경우 할인 조건을 제안한다.
4. 사용자 선택으로 확정된 예약을 확인하고 인계서를 검토한다.
5. 추가 확인 사항과 준비할 장비·부품·점검 항목을 등록한다.
6. 수리 완료를 처리하고 실제 확인한 원인, 작업 내용, 수리 전후 사진 등을 기록한다.

## 4. 기능 요구사항

### 4.1 사진·증상 접수 및 요청 기록

**주체:** 사용자, 시스템 · **근거:** 제4.1절, 제5.1절, 제6.3절

| ID | 기능명 | 요구사항 | 확인 기준 |
| --- | --- | --- | --- |
| FR-REQ-01 | 문제 접수 | 사용자는 문제 부위의 사진과 간단한 증상을 하나의 요청으로 등록할 수 있어야 한다. | 최초 사진 한 장과 증상 설명으로 요청을 생성하고 해당 사진·설명을 함께 조회할 수 있다. |
| FR-REQ-02 | 과거·추가 자료 등록 | 사용자는 과거에 촬영한 사진과 이후 촬영한 사진, 추가 설명을 기존 요청에 덧붙일 수 있어야 한다. | 추가 자료가 새 요청으로 분리되지 않고 기존 요청에 연결된다. |
| FR-REQ-03 | 사진 날짜 관리 | 날짜별 비교를 위해 사진의 촬영 날짜를 확인·입력할 수 있어야 한다. **명세화:** 업로드 시각과 촬영 날짜를 구분하고, 알 수 없는 날짜를 임의로 확정하지 않는다. | 과거 사진을 나중에 올려도 촬영 날짜 기준으로 정리되며, 날짜 미확인 상태를 구분할 수 있다. |
| FR-REQ-04 | 증상·조치 정보 수집 | 최초 발견 시점, 발생 위치·조건, 반복 여부, 시도한 조치 및 결과를 입력하거나 문답으로 보완할 수 있어야 한다. 제품 문제는 AS 안내에 필요한 제품 정보도 수집할 수 있어야 한다. | 입력한 정보가 요약·상담·인계서에서 재사용되며, 미확인 항목이 확정 사실로 바뀌지 않는다. |
| FR-REQ-05 | 요청 이력 조회 | 사용자는 자신의 요청에 연결된 사진, 문답, 경과, 상담·예약 및 완료 기록을 조회할 수 있어야 한다. | 한 요청에서 접수부터 처리 결과까지 연결된 기록을 확인할 수 있다. |
| FR-REQ-06 | 작업 지역 등록·수정 | **명세화:** 사용자는 기사 탐색 전에 실제 작업 지역을 시·군·구 및 읍·면·동 수준으로 등록·수정해야 한다. 최초 사진 접수나 자가 해결 안내에 상세 주소 입력을 요구하지 않는다. | 작업 지역이 기사 활동 지역 및 동선 조건 검사에 사용된다. 지역 미입력 시 적합 기사로 확정 표시하지 않고 입력을 요청하며, 수정 시 기존 추천·제안의 적합성을 재검사한다. |
| FR-REQ-07 | 상세 방문 정보 확인 | **명세화:** 사용자는 예약 확정 전에 상세 주소와 방문 연락처를 입력·확인하고, 저장된 작업 지역과 일치하는지 확인해야 한다. 확정 후 변경은 제6.2절의 변경 절차를 따른다. | 정보가 빠지거나 작업 지역과 불일치하면 보완 후 확정한다. 입력만으로 상담 기사에게 공개되지 않으며, 예약 확정 후 담당 기사에게 필요한 정보만 제공된다. |

### 4.2 AI 문제 파악 및 사용자 확인

**주체:** 사용자, AI, 시스템 · **근거:** 제4.1절, 제5.1절, 제5.3절

| ID | 기능명 | 요구사항 | 확인 기준 |
| --- | --- | --- | --- |
| FR-AI-01 | 증상 요약·분야 후보 | AI는 입력한 사진·설명을 바탕으로 증상을 요약하고 관련 수리 분야와 가능한 원인 후보를 제시해야 한다. | 요약에서 원본 증상을 확인할 수 있고, 가능한 원인이 실제 확인된 원인과 구분된다. |
| FR-AI-02 | 맞춤 추가 문답 | AI는 현재 정보에서 부족한 항목을 파악하여 추가 질문을 생성하고 답변을 요청 기록에 반영해야 한다. | 최초 발견 시점·발생 조건·반복 여부·시도한 조치 등 필요한 정보가 질문과 답변으로 보완된다. |
| FR-AI-03 | 정보 성격 구분 | 결과 화면은 사진에서 관찰한 사실, 사용자 설명, AI 추정, 미확인 사항을 명확히 구분해야 한다. | 같은 결과에서 각 정보의 성격을 식별할 수 있고, 추정이 현장 확인 사실로 표시되지 않는다. |
| FR-AI-04 | 분석 결과 확인·수정 | 사용자는 증상 요약과 수리 분야를 확인·수정한 뒤 다음 단계로 진행할 수 있어야 한다. | 사용자가 수정한 내용이 이후 사례 검색과 상담용 정보에 반영된다. |
| FR-AI-05 | 위험 신호와 판단 한계 표시 | AI는 가능한 위험 신호를 참고 정보로 제시하고, 사진만으로 원인·안전성·최종 수리비를 단정하지 않아야 한다. | 불확실한 사항과 현장 점검 필요 여부가 표시되며, 원인 후보가 확정 진단처럼 제시되지 않는다. |

| FR-PRO-05 | 확정 예약을 보호하는 일정 변경 | **명세화:** 기존 방문 일정의 추가·수정과 방문 가능 시간 변경 시에도 확정 예약의 작업·이동 시간을 포함한 충돌을 검사해야 한다. 충돌하는 변경은 저장하지 않고 해당 예약의 변경·취소 절차를 안내한다. | 확정 후 외부 일정을 추가하거나 가능 시간을 줄여도 확정 예약이 조용히 덮어써지거나 충돌 상태로 남지 않는다. 충돌을 해소한 변경만 반영되며, 변경과 신규 예약이 동시에 처리되어도 같은 규칙을 지킨다. |

### 4.6 요청 검토 및 상담

**주체:** 사용자, 기사, 시스템 · **근거:** 제4.1절, 제4.2절, 제5.2절, 제7.4절

| FR-CON-03 | 추가 질문·사진 요청 | 기사는 추가 질문이나 재촬영 사진을 요청하고 사용자는 해당 요청에 답변·사진을 추가할 수 있어야 한다. | 질문과 응답이 같은 요청·상담에 연결되어 이후 견적 및 방문 준비에 활용된다. |
| FR-CON-04 | 상담 이력 확인 | 사용자와 기사는 자신이 참여한 상담의 질문, 응답, 전달 자료, 견적을 조회할 수 있어야 한다. **명세화:** 다른 기사와의 상담은 서로 공개하지 않으며, 종료된 상담의 기사 열람 범위는 제6.3절을 따른다. | 각 참여자는 허용된 상담 이력을 확인할 수 있고, 다른 상담의 내용이나 종료 후 추가된 비공개 기록은 열람할 수 없다. |

| FR-FLX-01 | 방문 가능 조건 등록 | 사용자는 기사 탐색 전에 특정 희망 시각 또는 수일간의 방문 가능 기간·시간대를 등록·수정할 수 있어야 한다. **명세화:** 수정 시 추천·제안 조건을 재검사하며, 확정 예약이 있으면 변경 요청으로 처리한다. | 특정 시각 요청과 유연한 기간 요청을 구분한다. 수정된 조건에 맞지 않는 제안은 선택할 수 없고, 확정 예약은 합의 없이 바뀌지 않는다. |

| FR-FLX-03 | 인근 일정·빈 시간 추천 | 시스템은 기사 기존 방문 일정의 지역과 빈 시간대를 분석해 동선 효율이 높은 요청을 기사에게 우선 추천해야 한다. **명세화:** 적합 후보에 제6.4절의 추가 이동 시간 기준을 적용한다. | 작업·이동 시간을 포함해 충돌 후보를 제외하며, 다른 조건이 같은 복수 요청에서는 추가 이동 시간이 작은 요청이 우선된다. 추천 순서와 계산 근거를 기준 자료로 재현할 수 있다. |
| FR-FLX-04 | 기사 제안으로 예약 연결 | 기사는 추천 요청에서 사용자의 상담 상대 선택과 상담 수락을 거친 뒤 구체적 방문 시간·금액·작업 조건을 제시하고, 사용자는 이를 비교해 선택할 수 있어야 한다. 유연한 일정이 할인이나 최저가를 보장하지 않음을 안내해야 한다. | 동선 추천만으로 금액·예약이 확정되지 않고 상담 연결, 기사 제안, 사용자 선택을 거쳐 처리된다. |
| FR-FLX-05 | 동선 추천에서 상담으로 전환 | **명세화:** 사용자가 동선 제안 탐색을 선택하고 최소 공개 항목을 확인한 요청만 후보 기사에게 추천한다. 기사는 최소 정보를 보고 상담 참여 의사를 표시할 수 있으며, 사용자가 해당 기사를 선택하기 전에는 사진·상세 요약을 열람하거나 정식 견적을 발행할 수 없다. | 제6.3절의 단계별 정보만 공개된다. 참여 의사는 사용자에게 기사 후보로 표시되며 상담 수락·견적·예약으로 자동 전환되지 않는다. 사용자가 탐색을 중단하면 미선택 기사의 추천 목록에서 제외된다. |

### 4.9 예약 관리

### 4.10 고장 경과 기록 및 사진 분석

| FR-HIS-04 | 관찰 변화 표시 | 선정된 문제 유형에서 비교 가능한 사진의 외형 변화 영역을 표시하고 관찰되는 면적·색상 등의 변화를 설명해야 한다. | 표시 영역의 위치·범위와 변화 방향·면적·색상 설명이 기준 사진의 관찰 가능한 내용에 부합한다. 변화 없음도 결과로 표현하며 없는 변화를 만들어 표시하지 않는다. 변화 유무 판정과 사진 연결이 맞더라도 영역이나 설명이 틀리면 정확성 항목은 실패로 기록한다. 세부 판정은 제8.2절과 제8.4절을 따른다. |
| FR-HIS-05 | 사진 근거 연결 | 경과 설명 항목마다 근거가 되는 사진과 촬영 날짜를 연결해야 한다. | 요약의 변화 설명에서 해당 원본 사진·날짜를 확인할 수 있고 잘못된 사진을 근거로 연결하지 않는다. |
| FR-HIS-06 | 외형 변화·원인 분리 | 사진에서 보이는 변화와 내부 고장 원인·위험도 추정을 구분하여 표시해야 한다. | 물자국이 넓어진 관찰 사실만으로 특정 내부 원인이나 위험도를 확정하지 않는다. |
| FR-HIS-07 | 단일 사진·후속 보강 | 사진 한 장과 기본 문답만 있어도 경과 요약·인계서를 생성할 수 있어야 하며, 이후 사진이 추가되면 보강할 수 있어야 한다. | 사진쌍이 없다는 이유로 상담·예약이 막히지 않고, 비교 자료 부족을 표시한 뒤 후속 기록을 반영할 수 있다. |

## 6. 상태와 처리 규칙

### 6.1 요청 처리 단계

아래 상태 명칭은 기획서의 흐름을 구현하기 위한 **명세화 예시**이다. 화면 명칭이나 내부 저장 값은 달라도 되지만 각 단계의 의미와 진행 조건은 구분해야 한다. 경과 기록 추가는 별도 종료 상태가 아니며 진행 중인 요청에 계속 연결한다.

| 단계 | 진입·처리 조건 | 다음 진행 |
| --- | --- | --- |
| 접수·분석 중 | 최초 사진·증상 등록 후 문답과 분석을 수행한다. | 사용자 확인 후 해결 경로 선택 |
| 해결 경로 선택 | 사용자가 분석 결과를 확인·수정했다. | 자가 해결, 제조사 AS 안내, 기사 탐색 |
| 자가 해결 진행 | 적용 조건에 맞는 가이드를 선택했다. | 해결 시 결과 기록·종료, 미해결 시 같은 요청으로 기사 연결 |
| 제조사 AS 안내 | 확인된 제품 정보에 맞는 공식 경로를 안내한다. | 외부 공식 절차 이용. 외부 예약·완료를 플랫폼이 자동 확정하지 않는다. |
| 기사 탐색·상담 | 작업 지역·방문 조건을 등록하고, 직접 선택 또는 동선 추천을 통해 상담 상대를 선택한다. | 질문·응답, 견적 제안·비교. 거절·선택 해제 시 해당 상담만 종료하고 다른 기사 탐색·상담을 계속한다. |
| 예약 확정·방문 준비 | 사용자가 제안을 선택하고 시스템의 조건 검사를 통과했다. | 최신 인계, 추가 확인, 방문 준비, 필요시 변경·취소 |
| 작업 완료 | 담당 기사가 실제 작업 완료와 내용을 기록한다. | 완료 이력 조회, 별도 동의에 따른 사례 활용 |
| 자가 해결 종료 | 사용자가 해결 결과를 기록했다. | 기존 접수·조치 이력 조회 |

**명세화:** 요청 상태와 개별 상담·예약 상태는 분리한다. 예약 취소 시 요청은 기사 탐색·상담 단계로 돌아가고, 해당 예약은 취소 이력으로 남는다. 다른 기사와의 활성 상담이 없다면 사용자가 다시 상담 상대를 선택한다. 기존 사진·문답·경과는 재사용하되 이전 기사에게 새 기록이 자동 공개되지는 않는다. 한 상담의 거절만으로 요청 전체를 종료하지 않는다.

### 6.2 예약·견적 일관성 규칙

1. **상담 수락, 견적 제안, 예약 확정은 별개이다.** 기사 요청 수락이나 AI 추천만으로 예약을 확정하지 않는다.
2. **동선 추천은 방문 가능성과 금액을 대신 확정하지 않는다.** 시스템은 조건을 판별하고 기사가 시간·금액을 제안하며 사용자가 선택한다.
3. **중복 검사는 확정 시점에도 수행한다.** 예상 작업 시간과 적용한 이동 시간 가정을 포함해 일정 충돌을 확인한다.
4. **명세화:** 예약 변경은 새 조건을 양측이 확인하고 재검사를 통과한 후 반영한다. 변경 협의 중에는 기존 확정 정보를 구분해 유지한다.
5. **명세화:** 예약 취소는 해당 예약의 일정 점유를 해제하되, 기존 요청·상담·경과 기록을 자동 삭제하는 것으로 취급하지 않는다. 추가 예약을 진행할 때도 중복 검사를 적용한다.
6. **확정 금액과 추가 비용 조건을 구분한다.** 견적 조건을 현장 점검 전 무조건적인 최종 수리비로 표현하지 않는다.
7. **긴급 대응 안내를 우선한다.** 경과 사진을 더 모으거나 할인 조건을 기다리게 하는 흐름 때문에 필요한 접수가 지연되지 않도록 한다.
8. **명세화 — 견적의 유효성:** 발행할 때 기사가 유효 종료 시각을 지정하고 사용자에게 표시한다. 예약 확정 직전 시스템 기준 시각으로 만료 여부와 최신 버전을 검사한다. 수정본 발행 시 이전 버전은 대체됨으로 처리한다. 기사의 철회, 사용자의 제안 거절, 만료, 다른 제안으로 예약 확정이 발생하면 해당 미확정 제안은 선택할 수 없다. 확정에 사용한 제안은 당시 조건으로 보존하며 이후 수정·만료의 영향을 받지 않는다.
9. **명세화 — 방문 조건 변경:** 미확정 요청의 작업 지역·방문 가능 조건이 바뀌면 추천을 다시 계산하고 기존 제안은 재확인 필요로 전환한다. 기사가 새 조건으로 다시 발행한 제안만 선택할 수 있다. 확정 후 작업 지역·주소·방문 시간을 바꾸는 경우에는 변경 요청으로 처리하며, 양측 확인과 충돌 검사 전까지 기존 조건을 유지한다. 동일 장소의 연락처만 정정하는 경우에는 사용자 확인 후 담당 기사에게 수정된 연락처를 제공한다.
10. **명세화 — 일정 변경 시 보호:** 확정 예약과 충돌하는 기사 외부 일정 등록·수정이나 방문 가능 시간 축소는 저장하지 않는다. 기존 예약을 변경·취소하여 충돌을 해소한 뒤 다시 반영한다. 예약 확정과 일정 변경이 동시에 수행되어도 최종 저장 결과에 충돌이 없어야 한다.
11. **명세화 — 취소 가능 범위:** 사용자는 작업 완료 처리 전 예약을 취소할 수 있다. 완료된 예약에는 취소를 적용하지 않는다. 취소 시 일정 점유 해제, 요청의 기사 탐색·상담 복귀, 해당 기사의 접근 범위 변경을 함께 반영한다. 취소와 완료가 동시에 요청되면 먼저 확정된 상태를 기준으로 다른 처리를 거절하고 현재 상태를 안내한다. 취소 예약을 작업 완료로 바꿀 수 없다.
12. **명세화 — 변경 합의:** 변경을 요청한 쪽이 새 조건을 확인하고 상대가 해당 버전을 수락한 뒤 시스템 재검사를 통과하면 변경을 확정한다. 상대의 거절·요청 철회 시 기존 예약을 유지한다. 합의 도중 조건이 다시 수정되면 이전 수락은 새 조건의 수락으로 사용하지 않는다.

| 예약 취소 | 취소 상태와 당시 예약 조건, 해당 상담의 개인 식별 정보를 제외한 텍스트·견적 이력 | 취소 기사에게 사진·인계서·상세 주소·연락처 및 이후 재예약·경과 기록의 접근을 허용하지 않는다. 사용자 본인의 전체 이력은 유지한다. |
| 작업 완료 | 완료 시점의 해당 상담·인계 전달본과 작업 원인·내용·부품·전후 사진·예약 조건 | 담당 기사는 당시 작업 확인에 필요한 기록만 조회한다. 상세 주소·연락처는 텍스트·사진에서도 가리거나 제외하며, 완료 후 추가된 다른 자료나 새 예약은 공개하지 않는다. |
| 임대인·관리사무소 공유 | 사용자가 선택·확인한 증상·경과 요약, 발견 시점·발생 조건·조치 결과·미확인 사항 및 선택한 근거 사진 | 기사 상담·견적, 연락처, 상세 주소는 기본 제외한다. 공유 전 전달본을 확인하며, 전체 계정·다른 요청으로 접근이 확장되지 않도록 한다. |

동선 추천과 상담은 다음 순서로 연결한다.

1. 사용자가 작업 지역·방문 조건을 등록하고 동선 제안 탐색 여부와 최소 공개 항목을 확인한다.
2. 시스템은 적합 요청을 기사에게 추천한다. 기사는 최소 정보로 상담 참여 의사만 표시할 수 있다. 참여 의사는 견적이나 방문 확약이 아니다.
3. 사용자는 참여 의사를 표시한 기사의 프로필·사례를 확인하고 상담 상대를 개별 선택한다. **사례 탐색에서 기사를 직접 선택한 경우에는 작업 지역·방문 조건 등록은 유지하되, 동선 제안 탐색과 기사 참여 의사 단계를 생략하고 상담 요청으로 진행한다.**
4. 선택한 기사에게 허용된 사진·요약을 전달한다. 기사가 상담을 수락한 뒤 질문·응답과 정식 견적 제안을 진행한다.
5. 사용자가 유효한 제안을 선택하고 상세 방문 정보 및 시스템 조건 검사를 마치면 예약을 확정한다. 선택된 예약의 기사에게 상세 주소·연락처와 최신 인계서를 제공한다.

권한 변경은 화면뿐 아니라 자료 조회·원본 사진·내려받기 요청에도 적용한다. 이미 상대가 내려받은 파일의 회수까지 보장하는 의미는 아니다. 외부 공유 방식이 링크인 경우에는 지정한 전달본만 열람하도록 제한하고, 사용자가 공유를 철회하면 이후 열람을 차단한다. 파일 전달 방식에서는 전달 전에 선택한 범위만 포함된 결과물을 생성한다.

### 6.4 동선 추천의 비교 기준

아래는 원문의 동선 효율 우선 추천을 검증하기 위한 **명세화 규칙**이다.

1. 작업 분야·지역·사용자 가능 기간이 맞고, 예상 작업 시간과 이동 시간을 포함해 기존 일정 사이에 삽입 가능한 요청만 우선순위 비교 대상으로 삼는다.
2. 같은 빈 시간의 앞뒤 방문 위치를 A·B, 새 요청 위치를 R이라 할 때 추가 이동 시간은 `이동(A, R) + 이동(R, B) - 이동(A, B)`로 계산한다. 앞뒤 일정이 없는 경우에는 기준 자료에 명시한 출발·복귀 위치를 사용한다. 자료가 없으면 동선 효율을 미산정으로 표시하며 계산된 절감 효과처럼 제시하지 않는다.
3. 적합 후보는 가능한 삽입 구간 중 추가 이동 시간이 가장 작은 값을 기준으로 오름차순 정렬한다. 동률이면 요청 접수 시각, 추천용 식별자 순으로 정렬한다. 동선 효율만 미산정인 후보는 산정 가능한 후보 뒤에서 별도 표시하며, AI가 이동 값을 만들어 순위를 정하지 않는다. 작업·이동 시간 부족으로 충돌 여부까지 검사할 수 없는 요청은 적합 후보로 확정 표시하지 않고 보완을 요청한다.
4. 프로토타입은 지역 대표 위치와 고정된 모의 이동 시간표를 사용할 수 있다. 적용한 위치 단위·시간표·작업 소요 시간·출발 및 복귀 가정을 기록하고 동일 조건으로 비교한다. 사용자에게는 지역 단위 추정임을 안내하며 실제 도로 이동·도착 시각을 보장하지 않는다.
5. 긴급 요청은 할인 대기를 유도하는 순위 대상으로 처리하지 않고 즉시 대응 경로 안내를 우선한다. 순위는 할인율이나 예약을 확정하지 않으며 최종 시간·금액은 기사 제안과 사용자 선택에 따른다.

## 8. 모의평가 요구사항

**근거:** 기획서 제6.2절, 제6.4절, 제7.2절, 제7.3절. 이 절은 서비스의 일반 사용자 화면 기능과 구분되는 프로젝트 검증 요구사항이다.

### 8.1 평가 절차

1. 제8.3절에 따라 자료의 출처·활용 가능 여부·개인 식별 정보 부재를 확인하고, 접수 증상·사진, 수리 사례, 기사 전문 분야·지역·기존 일정, 사용자 가능 기간, 작업·비용 조건을 기준 시나리오로 구성한다.
2. **명세화:** 프로젝트 팀의 평가 담당자와 해당 기능 담당자는 평가 실행 전에 데이터셋, 정답 기준, 지표별 집계 단위·루브릭·목표값을 함께 확정하고 기준 버전을 기록한다. 서비스 결과를 확인한 뒤 유리한 기준으로 바꾸지 않는다.
3. 서비스 결과 생성 에이전트와 평가 에이전트의 역할 및 대화 맥락을 분리한다. 평가 에이전트에는 원본 입력, 정답 기준, 세부 평가 루브릭을 제공한다.
4. 사용자·기사 역할의 평가와 별도의 품질 평가를 통해 정보 충분성, 질문·준비사항의 적절성, 근거 일치도를 확인한다.
5. 날짜·시간·지역·금액은 AI 채점과 함께 규칙 기반 검사를 수행한다. 필수 기능 규칙의 통과 여부와 AI 출력의 품질 점수는 별도로 기록한다.
6. 항목별 점수, 판정 근거, 정보 누락·오류, 전체 평가 건수, 비교 불가·평가 보류 건수를 기록하고 제8.4절에 따라 완료 여부를 판정한다.

### 8.2 평가 대상과 자료

| 평가 대상 | 주요 지표 | 필요한 기준 자료 |
| --- | --- | --- |
| 증상 요약·분야 분류 | 분야 일치율, 필수 정보 포함률, 근거 없는 정보 포함 비율 | 원본 증상, 기준 분야, 필수 정보, 허용 추정 범위 |
| 사례 기반 기사 추천 | 추천 관련성, 추천 근거 일치도, 기본 조건 충족률 | 연관·무관 사례, 실제/모의 라벨, 기사 분야·지역·시간 |
| 일정·할인 예약 | 일정·지역 조건 충족률, 일정 충돌 건수, 금액 조건 일관성 | 즉시 예약 가능·충돌·인근 일정 연계 시나리오, 동일 작업·비용 조건, 이동 부담이 서로 다른 적합 요청 |
| 사진·경과 분석 | 기준 사진쌍 판정 일치율, 변화 영역·설명 정확성, 근거 연결 정확성, 판단 유보 적절성 | 변화 있음·없음·비교 불가 사진쌍과 증상 기록, 사진쌍별 허용 변화 영역·관찰 설명 및 필수 출력 항목 |
| 기사 인계서 | 원본 정보 일치도, 필수 정보 포함률, 정보 누락·왜곡 건수 | 발견 시점, 발생 조건, 시도한 조치·결과, 미확인 사항, 사진 근거 |
| 추가 질문·방문 준비사항 | 질문·준비사항 적절성, 불필요한 반복 질문 비율 | 이미 제공한 정보, 필수 확인 질문, 허용되는 준비사항 |

사진 변화 분석은 **변화 유무 판정, 변화 영역·설명의 정확성, 사진 근거 연결을 구분해 평가**한다. **명세화:** 평가 전에 기준 사진쌍별로 관찰 가능한 변화 위치·범위·방향과 면적·색상의 허용 설명, 필수 출력 항목 및 영역 표시의 허용 범위를 정한다. 면적은 사진에서 확인할 수 있는 확대·축소 등의 설명으로 평가할 수 있으며, 실제 면적의 정밀 측정을 요구하지 않는다. 변화가 없는 사진쌍은 변화 없음 표시와 허위 영역·설명 부재를 확인하고, 비교 불가 사진쌍은 판단 유보·재촬영 안내를 검증한다.

일정·할인 예약은 **동일한 작업 범위와 비용 조건을 유지한 기준 시나리오**에서 평가한다. **명세화:** 작업 종류·수량·예상 소요 시간, 할인 전 비용 항목과 추가 비용 조건을 고정하고, 방문 가능 기간·기존 일정·이동 부담 등 비교하려는 조건과 기사 할인 제안만 구분해 기록한다. 작업 범위 축소나 부품비 제외로 낮아진 금액을 동선 연계 할인 효과로 계산하지 않는다.

이동 시간 비교는 동일한 가정 아래 계산한 시뮬레이션 값으로 수행한다. 동선 우선순위 검증에는 지역·분야·시간 조건을 모두 충족하지만 이동 부담이 다른 요청을 함께 배치하고, 사전에 정한 효율 기준에 따른 추천 순서를 확인한다. 모의평가 결과는 통제된 시나리오의 출력 품질과 조건 충족도를 나타내며, 실제 현장의 비용 절감액·수리 만족도·이동 시간 절감 효과를 입증한 값으로 사용하지 않는다.

### 8.3 평가 자료의 출처와 사용 조건

평가 데이터셋은 출처가 명확한 수리·제품 안내 자료, 활용 가능한 실제·재현 사진, 팀이 설계한 기준 시나리오 및 모의 기사 프로필·일정으로 구성한다. 출처 관리 대상은 수리 사례뿐 아니라 평가에 사용되는 모든 안내 자료·사진·일정 및 정답 근거를 포함한다.

| 자료 구분 | 확인·기록할 내용 | 사용 조건 |
| --- | --- | --- |
| 수리·제품 안내 자료 | 원자료 위치, 제공자, 확인일·버전, 사용 범위 | 출처와 활용 가능 여부가 확인된 자료만 가이드·정답 근거로 사용한다. |
| 실제·재현 사진 및 수리 사례 | 제공·촬영 출처, 실제/재현·실제/모의 구분, 촬영 날짜 또는 미확인 상태, 필요한 활용 동의 | 모의 사례를 실제 실적으로 표시하지 않는다. 출처·활용 가능 여부가 불명확한 자료는 확인 전까지 평가에서 제외한다. |
| 기준 시나리오·모의 프로필·일정 | 작성 주체, 시나리오 식별자·버전, 작업·지역·시간·금액 가정 | 실제 인물의 식별 정보를 포함하지 않고, 비교 시나리오 간 고정 조건과 변경 조건을 구분한다. |
| 정답·평가 기준 자료 | 필수 정보, 허용 추정 범위, 원본 사진·설명 근거, 조건별 기대 결과, 검토자·버전 | 서비스 출력 생성 전에 준비하고 원본 자료와 연결한다. |

**명세화:** 자료별 출처·사용 조건·확인 결과를 평가 자료 목록에 남기고, 비식별화가 필요하면 처리 결과도 함께 기록한다. 실제 개인 식별 정보가 남았거나 필요한 동의·활용 가능 여부가 확인되지 않은 자료는 평가 입력에 포함하지 않는다. 제외·교체 내역과 사유는 데이터셋 버전에 남긴다.

### 8.4 지표 정의와 완료 판정

아래 집계 규칙은 기획서의 지표를 재현 가능하게 계산하기 위한 **명세화**이다. 지표별 필수 항목 목록, 허용 답안, 점수 척도와 목표값은 평가 전에 확정한다. 아래 표의 평가 대상은 사전에 지정한 전체 대상 중 해당 지표를 판정할 수 있는 항목이며, 보류 항목은 별도 집계한다. 비율은 해당 분자와 분모를 함께 보고하며, 분모가 없으면 성공으로 처리하지 않고 `산출 불가`로 표시한다.

| 지표 유형 | 집계 단위와 산정 기준 |
| --- | --- |
| 분야 일치율·기준 사진쌍 판정 일치율 | 정답 기준과 일치한 요청 또는 사진쌍 수 / 해당 지표의 판정 가능한 전체 요청 또는 사진쌍 수 |
| 변화 영역·설명 정확성 | 제8.2절의 필수 출력과 허용 기준을 모두 충족한 사진쌍 수 / 기준상 비교 가능하고 정확성 판정이 가능한 전체 평가 사진쌍 수. 변화 있음·없음 결과를 각각 집계하고 전체 결과도 보고한다. 영역 또는 설명 오류, 필수 출력 누락은 실패로 기록하며, 변화 유무 판정이나 사진 연결이 맞았다는 이유로 성공 처리하지 않는다. 오류 종류와 판정 근거를 함께 남긴다. |
| 필수 정보 포함률 | 정확히 반영된 필수 항목 수 / 기준 시나리오에서 요구한 전체 필수 항목 수. 정보가 없을 때 미확인으로 표시해야 하는 항목도 기준에 포함한다. |
| 근거 없는 정보 포함 비율 | 원본 근거 또는 허용 추정 범위를 벗어난 사실 주장 수 / 평가 대상 출력의 전체 사실 주장 수. 추정 표시 유무와 허용 여부를 함께 판정한다. |
| 추천 근거 일치도·사진 근거 연결 정확성·원본 정보 일치도 | 원본과 일치한 근거 연결 또는 정보 항목 수 / 평가 대상 전체 근거 연결 또는 정보 항목 수. 항목 분할 기준은 평가 전에 고정한다. |
| 기본 조건 충족률·일정·지역 조건 충족률 | 요구된 조건을 모두 충족한 추천 후보 또는 제안 수 / 조건 충족 대상으로 제시된 전체 후보 또는 제안 수. 추천 누락·후보 없음은 별도로 기록해 빈 결과를 성공으로 집계하지 않는다. |

**평가 보류·비교 불가 처리**

- 판단 근거가 부족해 채점할 수 없는 출력은 `평가 보류`로 기록하고 사유를 남긴다. 지표별 전체 대상 수, 판정 가능 수, 보류 수와 보류 비율을 함께 제시한다. 보류 건을 성공 건으로 계산하거나 보고에서 숨기지 않는다.
- 사진쌍의 `비교 불가`는 정상적인 정답 분류가 될 수 있다. 기준상 비교 불가인 사진쌍에 대해 판단을 유보하고 재촬영을 안내했는지는 판정 일치율과 유보 적절성 평가에 포함한다. 사진 비교 불가와 평가자의 채점 보류를 구분한다.
- 변화 영역·설명 정확성의 평가 대상 여부는 서비스 출력이 아닌 사전 정답 기준으로 정한다. 기준상 비교 가능한 사진쌍에 서비스가 비교 불가를 출력하거나 필수 결과를 누락하면 정확성 실패로 기록하며 평가 대상에서 제외하지 않는다. 기준상 비교 불가인 사진쌍은 해당 정확성 지표에서 제외한 건수를 별도 보고하고, 변화를 단정한 출력은 사진쌍 판정·판단 유보 평가에 반영한다.
- 기준이나 자료가 바뀌면 버전과 변경 사유를 기록하고 영향을 받는 항목을 다시 평가한다. 서로 다른 기준의 점수를 설명 없이 합산하지 않는다.

**완료 판정**

1. 기능 검수는 각 FR의 확인 기준과 제7장의 대응 AC를 모두 확인한다. 접근 통제, 동의 분리, 일정 충돌 방지 등 필수 규칙 위반은 AI 품질 평균 점수로 상쇄하지 않는다.
2. AI 품질은 사전에 확정한 지표별 목표와 허용 가능한 보류 범위를 적용해 판정한다. 목표값을 아직 정하지 않은 경우 결과와 근거는 보고할 수 있지만 해당 품질 검수를 완료로 표시하지 않는다.
3. **명세화:** 평가 담당자와 기능 담당자는 기능 검수 결과, 품질 판정, 보류·오류 처리 결과 및 사용한 기준 버전을 함께 확인한다. 미실행·실패·기준 미정 항목이 남으면 해당 기능의 검수는 미완료로 기록한다.
