## 1. 검토 결과와 분류 기준

요구사항 명세서는 기획서의 핵심 기능을 유지하면서 **상담 연결 절차, 견적 만료·버전 관리, 예약 변경·취소 정책, 종료 후 정보 접근 권한, 동선 정렬 공식, 검수 완료 조건**을 추가로 정했다.

이 보고서에서 ‘추가’는 **기획서 v2.3이 직접 정하지 않았는데 명세서에서 새로 정한 내용**을 뜻한다. 추가됐다는 사실만으로 부적절한 요구사항이라고 판단하지 않는다. 기존 기능을 실제로 구현하기 위한 구체화도 포함하되, 새로운 정책 선택과 구분한다.

| 분류 | 의미 | 예시 |
| --- | --- | --- |
| 추가 정책·절차 | 원문이 확정하지 않은 동작·제약·선택 방식을 명세서가 정했다. | 견적 유효 종료 시각, 상담 참여 의사 단계, 동선 정렬 공식 |
| 기존 기능 구체화 | 원문 기능의 처리·조회·예외·검증 기준을 더 자세히 정했다. | 변경된 인계서 재확인, 저장 실패 시 재시도, 사진 정확성 실패 기준 |
| 추가 결정 과제 | 아직 값이나 구현 방식을 정하지 않았지만 결정 책임과 시점을 부여했다. | 사진 크기 제한, 인증 방식, 평가 목표값 |
| 범위·문서 구조 명시 | 구현 제외 대상이나 요구사항 관리 방식을 명확히 했다. | 관리자 콘솔 제외, FR·AC 식별자, 요구사항 추적표 |
| 기존 내용 | 표현이나 구조는 달라졌지만 기능·원칙이 원문에도 있다. | 세 가지 핵심 기능, 임대인 공유, AI 평가 에이전트 분리 |

판정에는 `명세화` 표시뿐 아니라 각 FR의 확인 기준, 제6장의 처리 규칙, 제7장의 AC, 제8장의 평가 규칙, 제9장의 결정 과제를 함께 사용했다. 같은 내용이 여러 절에 반복되는 경우에는 아래 항목으로 묶었다. 표의 행 수는 독립적인 신규 기능 개수를 뜻하지 않는다.

또한 이 보고서는 **현재 두 문서의 내용 차이**를 분석한 것이다. 요구사항 명세서 1.1에서 1.2로 변경된 내용만을 분석하거나 Git 작성 이력을 추정한 문서가 아니다.

### 구현 범위에 영향이 큰 추가사항

| 영역 | 기획서에서 정한 수준 | 명세서에서 추가로 정한 수준 |
| --- | --- | --- |
| 상담 연결 | 조건에 맞는 기사 탐색·상담·제안 | 동선 탐색 선택, 최소 공개 확인, 기사 참여 의사, 사용자 선택, 기사 수락의 순서 |
| 견적 | 작업·금액·방문 조건 제안과 비교 | 유효기간, 버전, 철회·거절·대체 상태, 확정 당시 조건 보존 |

| 정보 관리 | 선택 상대에게 필요한 정보 전달, 단계별 공개 통제 | 단계별 공개 필드, 상담 종료·예약 취소·완료 후 열람 범위, 원본 파일 접근 통제 |
| 동선 추천 | 효율이 높은 요청 우선 추천 | 추가 이동 시간 공식, 삽입 구간 선택, 동률 정렬, 미산정 후보 처리 |
| 검수 | 시나리오·지표·근거에 따른 모의평가 | 지표별 산식, 사전 목표값, 평가 버전, 필수 규칙 위반 및 미정 항목의 완료 판정 |

## 2. 접수 정보와 기사 연결에 추가된 내용

기획서에는 사진 접수, 지역·일정에 맞는 기사 탐색, 선택한 기사와 상담하는 흐름이 있다. 다음 입력 조건과 연결 절차까지는 정하지 않았다.

원문 근거: [기획서 §4.1 사용자 이용 과정][plan-user], [§5.1 사용자 기능][plan-user-features], [§7.4 정보 관리][plan-information].

| 항목 | 명세서에서 추가·구체화한 내용 | 명세서 근거 |
| --- | --- | --- |
| 촬영 날짜 처리 | 촬영 날짜와 업로드 시각을 분리하고 사용자가 촬영 날짜를 확인·입력한다. 날짜를 모르면 임의 확정하지 않고 미확인으로 관리한다. | [FR-REQ-03][spec-intake] |
| 작업 지역의 입력 단위·시점 | 기사 탐색 전에 시·군·구 및 읍·면·동 수준의 작업 지역을 등록한다. 지역이 없으면 적합 기사로 확정 표시하지 않고 입력을 요청한다. 최초 사진 접수·자가 해결에는 상세 주소를 요구하지 않는다. | [FR-REQ-06][spec-intake] |
| 상세 주소·연락처의 예약 조건화 | 예약 확정 전에 상세 주소·방문 연락처를 입력·확인하고 작업 지역과 일치하는지 확인한다. 누락·불일치 시 확정을 막는다. 입력했다는 이유만으로 상담 기사에게 공개하지 않는다. | [FR-REQ-07][spec-intake] |
| 제조사 미확인 처리 | 제조사를 특정할 수 없으면 추가 확인을 요청한다. 외부 제조사 예약·완료를 플랫폼 내부에서 자동 확정하거나 완료된 것처럼 표시하지 않는다. | [FR-SOL-04][spec-solutions], [§6.1][spec-state] |
| 추천 후보 부족 처리 | 연관 사례나 조건에 맞는 기사가 없다는 상태를 안내하고, 입력·탐색 조건을 보완해 다시 탐색하게 한다. 없는 사례·경험·일정을 만들어 표시하지 않는다. | [FR-MAT-06][spec-matching] |
| 복수 기사 상담 | 사용자가 여러 상담 상대를 개별 선택할 수 있다고 명시한다. 기사별 상담 권한과 이력을 분리하고 다른 기사와의 상담은 공개하지 않는다. 자동 추천이나 기사 참여 의사는 사용자 선택을 대신하지 않는다. | [FR-CON-01·04][spec-consultation] |
| 동선 탐색의 사용자 선택 | 사용자가 동선 제안 탐색 여부와 최소 공개 항목을 확인한 요청만 후보 기사에게 추천한다. 탐색을 중단하면 미선택 기사의 추천 목록에서 제외한다. | [FR-FLX-05][spec-flexible] |
| 기사의 상담 참여 의사 단계 | 추천받은 기사는 최소 정보로 참여 의사만 표시한다. 이후 사용자 상담 상대 선택 → 허용 자료 공개 → 기사 상담 수락 → 정식 견적 순서로 진행한다. 참여 의사만으로 사진·상세 요약 열람이나 정식 견적 발행 권한이 생기지 않는다. | [FR-FLX-04·05][spec-flexible], [§6.3][spec-disclosure] |
| 직접 선택 경로의 예외 | 사용자가 사례 탐색에서 기사를 직접 선택하면 동선 탐색·기사 참여 의사 단계를 생략한다. 작업 지역·방문 조건 등록은 유지한다. | [§6.3 연결 절차 3번][spec-disclosure] |

특히 **동선 탐색 선택과 기사 참여 의사 단계**는 사용자·기사 화면과 처리 상태가 추가되는 부분이다. 원문의 ‘조건에 맞는 기사에게 연결하고 기사가 제안한다’는 설명만으로 이 절차가 반드시 정해지는 것은 아니다.

## 3. 견적·일정·예약에 추가된 정책

기획서에는 견적 제안·비교, 예약 확정·조회·변경·취소, 중복 예약 방지가 있다. 아래 유효기간·버전·합의·동시 처리 규칙은 명세서에서 정했다.

원문 근거: [기획서 §5.1 예약 관리][plan-user-features], [§5.2 견적 및 일정 제안][plan-technician-features], [§6.2 할인 예약][plan-flexible], [§7.2 중복 예약 평가][plan-evaluation].

| 항목 | 명세서에서 추가한 내용 | 명세서 근거 |
| --- | --- | --- |
| 견적 유효기간 | 기사가 발행 시 유효 종료 시각을 지정하고 사용자에게 표시한다. 예약 확정 직전에 시스템 기준 시각으로 만료 여부를 검사한다. | [FR-QTE-05][spec-quotes], [§6.2, 8번][spec-consistency] |
| 견적 버전 관리 | 수정 견적을 새 버전으로 발행하고 이전 버전을 ‘대체됨’으로 처리한다. 사용자는 상태·버전·유효 시각·변경 조건을 확인한다. 이전 화면에서 오래된 견적을 확정할 수 없다. | [FR-QTE-05][spec-quotes], [§6.2, 8번][spec-consistency] |
| 견적 선택 불가 조건 | 만료, 기사 철회, 사용자 거절, 조건 변경, 다른 제안으로 예약 확정 시 해당 미확정 견적을 선택할 수 없게 한다. 견적 철회·사용자 거절이라는 처리도 구체화됐다. | [§6.2, 8번][spec-consistency] |
| 확정 당시 견적 보존 | 예약에 사용한 견적은 당시 조건으로 보존한다. 이후 수정·만료가 확정 예약의 조건을 바꾸지 않는다. | [FR-QTE-05][spec-quotes], [§6.2, 8번][spec-consistency] |
| 예약 전 지역·방문 조건 변경 | 추천을 다시 계산하고 기존 견적을 재확인 필요 상태로 전환한다. 기사가 새 조건으로 재발행한 견적만 선택할 수 있다. | [FR-FLX-01][spec-flexible], [§6.2, 9번][spec-consistency] |
| 요청당 활성 예약 제한 | 기사 시간대 중복뿐 아니라 같은 요청에 서로 다른 활성 확정 예약이 생기는 것도 금지한다. 반복 확정·동시 확정에도 적용한다. | [FR-RES-02][spec-reservations] |
| 확정 시 최신 조건 재검사 | 견적 조회 후 바뀔 수 있는 조건을 예약·변경 확정 시 다시 검사한다. 충돌 검사에는 예상 작업 시간과 이동 시간 가정을 포함한다. | [FR-ERR-03][spec-errors], [§6.2, 3번][spec-consistency] |
| 기사 일정 수정의 제한 | 확정 예약과 충돌하는 외부 일정 추가·수정이나 방문 가능 시간 축소를 저장하지 않는다. 기존 예약의 변경·취소로 충돌을 해소한 뒤 반영한다. 일정 수정과 신규 예약 확정이 동시에 발생해도 충돌을 막는다. | [FR-PRO-05][spec-profiles], [§6.2, 10번][spec-consistency] |
| 예약 변경 합의 | 변경 요청자가 새 조건을 확인하고 상대가 해당 버전을 수락한 뒤 시스템 재검사를 통과해야 변경된다. 협의 중에는 기존 예약을 유지한다. 거절·철회 시에도 기존 예약을 유지한다. 조건이 다시 수정되면 이전 수락을 재사용하지 않는다. | [FR-RES-04][spec-reservations], [§6.2, 4·12번][spec-consistency] |
| 주소 변경과 연락처 정정의 구분 | 확정 후 작업 지역·주소·방문 시간 변경은 양측 확인과 충돌 검사를 거친다. 동일 장소의 연락처만 정정할 때는 사용자 확인 후 담당 기사에게 제공한다. | [§6.2, 9번][spec-consistency] |
| 취소 가능 시점 | 사용자는 작업 완료 처리 전까지만 예약을 취소할 수 있다. 완료된 예약은 취소할 수 없고, 취소된 예약을 작업 완료로 바꿀 수도 없다. | [§6.2, 11번][spec-consistency] |
| 취소·완료의 동시 요청 | 먼저 확정된 상태를 기준으로 다른 처리를 거절하고 현재 상태를 안내한다. | [§6.2, 11번][spec-consistency] |
| 취소 후 처리 | 일정 점유를 해제하고 요청을 기사 탐색·상담으로 돌린다. 취소 이력과 기존 요청·상담·경과는 유지하며 기사 접근 범위도 함께 변경한다. 추가 예약 시에도 중복 검사를 적용한다. | [§6.2, 5·11번][spec-consistency] |
| 요청·상담·예약 상태 분리 | 요청 전체와 개별 상담·예약 상태를 분리한다. 한 기사의 거절이나 선택 해제로 요청 전체를 종료하지 않는다. 취소 후 활성 상담이 없으면 사용자가 상담 상대를 다시 선택한다. | [§6.1][spec-state] |

지역·방문 조건 변경 시의 정책은 단순히 부적합 견적만 숨기는 것보다 강하다. 명세서 §6.2는 **기존 제안을 재확인 필요로 전환하고 기사 재발행본만 선택하도록** 정한다.

원문 근거: [기획서 §7.4 정보 관리 요구사항][plan-information]. 아래 모든 단계의 세부 근거: [명세서 §6.3 정보 전달 단계][spec-disclosure], [FR-INF-01~05][spec-information].

| 단계 | 새로 정한 공개·차단 기준 |
| --- | --- |
| 미선택 기사의 동선 추천 | 비식별 추천용 식별자, 수리 분야, 시·군·구/읍·면·동, 가능 기간·시간대, 예상 작업 시간과 미확정 여부만 제공한다. 이름·연락처·상세 주소·자유 입력 증상·문답·사진·인계서는 제외한다. 추천용 식별자로 원본 요청에 접근할 수 없다. |
| 선택한 기사와 상담 | 사용자가 확인한 요약과 선택한 사진·답변만 제공한다. 상세 주소·연락처·다른 상담은 제외한다. 텍스트·사진 내부의 주소·연락처·개인 식별 표지도 가리거나 제외한 전달본을 사용한다. |
| 예약 확정 후 방문 준비 | 확정 기사에게만 최신 인계서와 상세 주소·연락처를 공개한다. 추가·수정 자료는 사용자 확인 후 새 전달본으로 제공한다. 다른 기사와의 상담은 종료 처리한다. |
| 상담 거절·선택 해제·다른 기사 확정 | 종료된 기사는 당시 질문·응답·견적 중 식별 정보를 제외한 이력만 볼 수 있다. 접수 원본·사진·인계서·주소·연락처·후속 기록은 차단한다. 재상담에는 새 선택과 공개 범위 확인이 필요하다. |
| 예약 취소 | 취소 상태·당시 예약 조건·비식별 상담 텍스트·견적 이력만 허용한다. 사진·인계서·상세 주소·연락처·이후 재예약·경과 기록은 차단한다. 사용자 본인의 전체 이력은 유지한다. |
| 작업 완료 | 담당 기사는 완료 시점의 상담·인계 전달본과 작업 원인·내용·부품·전후 사진·예약 조건 중 당시 작업 확인에 필요한 기록만 조회한다. 상세 주소·연락처는 텍스트·사진에서도 가리거나 제외한다. 완료 후 추가 자료·새 예약은 공개하지 않는다. |
| 임대인·관리사무소 공유 | 사용자가 선택·확인한 요약과 근거 사진을 제공한다. 기사 상담·견적, 연락처, 상세 주소는 기본 제외한다. 공유로 전체 계정이나 다른 요청에 접근할 수 없게 한다. |
| 포트폴리오·AI 별도 활용 | 기본 중개와 별도 활용을 구분하는 데 더해, 공개 포트폴리오와 AI 학습·분석 사이에서도 동의를 독립적으로 확인한다. 동의 누락이나 비식별화 미완료·실패 시 활용을 차단한다. |

원문에도 동의·비식별화 원칙은 있다. **추가된 것은 목적 간 독립 처리, 단계별 필드, 종료 후 권한, 실패 시 차단 방식**이다.

### 4.1 자료 접근과 외부 공유의 추가 규칙

| 항목 | 추가한 처리 |
| --- | --- |
| 화면 외 접근 통제 | 자료 조회, 원본 사진 주소, 다운로드 경로에도 같은 권한을 적용한다. 요청 식별자를 알아도 권한 밖의 자료를 열람할 수 없다. |
| 요청 전체 권한 부여 금지 | 특정 필드가 필요하다는 이유로 요청 전체의 열람 권한을 부여하지 않는다. |
| 공유 링크의 범위 | 링크 방식을 선택하면 지정한 전달본만 열람할 수 있게 한다. |
| 공유 링크 철회 | 사용자가 공유를 철회하면 이후 열람을 차단한다. |
| 파일 공유의 범위 | 파일 방식은 전달 전에 사용자가 선택한 범위만 담은 결과물을 생성한다. |
| 파일 회수의 한계 | 이미 상대가 내려받은 파일의 회수까지 보장한다는 의미는 아니라고 명시한다. |

## 5. 동선 추천에 추가된 계산·정렬 기준

기획서는 동선 효율이 높은 요청의 우선 추천과 동일 가정의 이동 시간 시뮬레이션을 요구한다. 구체적인 계산 공식과 동률 처리법은 없다.

원문 근거: [기획서 §6.2 일정 유연성과 기사 동선을 활용한 할인 예약][plan-flexible]. 추가 규칙 근거: [명세서 FR-FLX-03][spec-flexible], [§6.4 동선 추천의 비교 기준][spec-route].

| 항목 | 명세서에서 새로 정한 기준 |
| --- | --- |
| 비교 대상 | 분야·지역·사용자 가능 기간이 맞고, 작업·이동 시간을 포함해 기존 일정 사이에 삽입 가능한 요청만 순위 비교 대상으로 삼는다. |
| 추가 이동 시간 공식 | 앞뒤 방문 위치가 A·B이고 새 요청이 R이면 `이동(A, R) + 이동(R, B) - 이동(A, B)`로 계산한다. |
| 앞뒤 일정이 없는 경우 | 기준 자료에 명시한 출발·복귀 위치를 사용한다. 필요한 자료가 없으면 동선 효율을 미산정으로 표시한다. |
| 후보별 비교 값 | 가능한 삽입 구간 중 추가 이동 시간이 가장 작은 값을 사용한다. |
| 정렬 순서 | 추가 이동 시간 오름차순으로 정렬한다. 동률이면 요청 접수 시각, 추천용 식별자 순으로 정렬한다. |
| 효율만 미산정인 후보 | 산정 가능한 후보 뒤에 별도로 표시한다. AI가 이동 값을 만들어 순위를 정할 수 없다. |
| 충돌 검사도 불가능한 후보 | 작업·이동 시간 부족으로 충돌 여부를 확인할 수 없으면 적합 후보로 확정 표시하지 않고 보완을 요청한다. |
| 시뮬레이션 구현 | 지역 대표 위치와 고정 모의 이동 시간표를 사용할 수 있다. 위치 단위·시간표·작업 시간·출발·복귀 가정을 기록한다. |
| 사용자 안내 | 지역 단위 추정임을 알리고 실제 도로 이동·도착 시각을 보장하지 않는다. |
| 긴급 요청의 순위 처리 | 기존의 긴급 대응 우선 원칙을 구체화해, 긴급 요청을 할인 대기를 유도하는 순위 대상으로 처리하지 않는다. |

이 중 **추가 이동 시간 공식, 후보별 최솟값 선택, 동률 정렬 기준**은 원문의 목적을 구현하는 여러 방법 중 명세서가 특정 방법을 선택한 정책이다.

## 7. 평가와 검수에 추가된 내용

| 사진별 허용 정답 작성 | 사진쌍별 변화 위치·범위·방향, 면적·색상 허용 설명, 필수 출력, 영역 표시 허용 범위를 사전에 정한다. 실제 면적의 정밀 측정까지 요구하지 않고 확대·축소 등의 설명으로 평가할 수 있다. | [§8.2][spec-evaluation-data] |
| 할인 비교의 통제 항목 | 동일 작업·비용 조건을 작업 종류·수량·예상 시간·할인 전 비용 항목·추가 비용 조건으로 구체화한다. 작업 축소나 부품비 제외로 낮아진 금액을 동선 할인 효과로 계산하지 않는다. | [§8.2][spec-evaluation-data] |
| 동선 순위 검증 자료 | 지역·분야·시간은 모두 적합하지만 이동 부담이 다른 요청을 함께 배치해 정해진 효율 기준대로 순위가 나오는지 확인한다. | [AC-06][spec-acceptance], [§8.2][spec-evaluation-data] |
| 평가 자료 관리 목록 | 출처 관리 대상을 모든 안내 자료·사진·일정·정답 근거로 구체화한다. 자료별 원자료 위치·제공자·확인일·버전·사용 범위, 촬영 출처·날짜·동의, 시나리오 작성자·식별자·가정, 정답 검토자·버전을 기록한다. | [§8.3][spec-sources] |
| 자료 제외·교체 기록 | 출처·활용 가능 여부·필요 동의가 불명확하거나 식별 정보가 남은 자료는 평가에서 제외한다. 비식별화 결과, 자료 제외·교체 내역과 사유를 데이터셋 버전에 남긴다. | [§8.3][spec-sources] |

### 7.2 평가 지표의 계산·실패 기준

지표 이름 대부분은 원문에도 있다. 아래 계산 단위와 세부 실패 처리법은 [명세서 §8.4][spec-metrics]에서 정했다.

| 지표·상황 | 추가된 계산·판정 규칙 |
| --- | --- |
| 비율 지표 공통 | 분자·분모를 함께 보고한다. 분모가 0이면 성공이 아니라 `산출 불가`로 표시한다. |
| 분야·사진쌍 판정 일치율 | 정답과 일치한 요청·사진쌍 수를 해당 지표의 판정 가능한 전체 요청·사진쌍 수로 나눈다. |
| 변화 영역·설명 정확성 | 필수 출력과 허용 기준을 모두 만족한 사진쌍을 성공으로 센다. 변화 있음·없음을 각각 집계하고 전체 결과도 보고한다. 영역·설명 오류와 출력 누락을 실패로 기록하고 오류 종류·근거를 남긴다. |
| 필수 정보 포함률 | 정확히 반영한 필수 항목 수를 전체 필수 항목 수로 나눈다. 정보가 없을 때 ‘미확인’으로 표시해야 하는 항목도 기준에 포함한다. |
| 근거 없는 정보 비율 | 원본·허용 추정 범위를 벗어난 사실 주장 수를 전체 사실 주장 수로 나눈다. 추정 표시 여부와 허용 여부를 함께 판정한다. |
| 근거·원본 정보 일치도 | 일치한 근거 연결·정보 항목 수를 전체 대상 항목 수로 나눈다. 항목을 나누는 기준을 사전에 고정한다. |
| 조건 충족률 | 모든 요구 조건을 충족한 후보·제안을 센다. 추천 누락·후보 없음을 별도 기록해 빈 결과를 성공으로 집계하지 않는다. |
| 금액 조건 일관성 | 작업·출장·부품·할인·추가 비용 조건이 유지된 제안의 비율을 계산하고 원본과 달라진 항목도 기록한다. |
| 충돌·누락·왜곡 건수 | 오류가 발생한 출력 건수와 오류 항목 수를 구분하고 전체 평가 건수도 함께 보고한다. |
| 관련성·유보·질문·준비사항 점수 | 사전 고정 척도와 단계별 판정 예시로 채점한다. 개별 점수·근거·판정 가능 건수와 평균 계산에 사용한 합계·건수를 기록한다. |
| 반복 질문 비율 | 불필요한 반복 질문 수를 전체 질문 수로 나눈다. 필수 질문 누락을 별도 기록해 질문을 생성하지 않은 결과가 고품질로 처리되지 않게 한다. |

### 7.3 평가 보류·비교 불가·완료 판정

| 항목 | 추가된 규칙 |
| --- | --- |
| 평가 보류 보고 | 지표별 전체 대상 수·판정 가능 수·보류 수·보류 비율과 사유를 제시한다. 보류를 성공으로 계산하거나 숨기지 않는다. |
| 사진 비교 불가와 채점 보류 분리 | 사진이 비교 불가라는 것은 정상 정답일 수 있으므로 평가자의 채점 불가와 구분한다. 비교 불가 사진에서 판단 유보·재촬영 안내가 적절했는지 평가한다. |
| 분모에서 임의 제외 금지 | 정답 기준상 비교 가능한 사진을 서비스가 ‘비교 불가’로 출력하거나 필수 결과를 누락하면 정확성 실패다. 평가 대상에서 빼지 않는다. |
| 정답상 비교 불가인 사진 | 변화 영역·설명 정확성 지표에서 제외한 건수를 별도 보고한다. 이 사진에서 변화를 단정한 출력은 사진쌍 판정·판단 유보 평가에 반영한다. |
| 기준 변경 관리 | 기준·자료가 바뀌면 버전·사유를 기록하고 영향을 받는 항목을 재평가한다. 다른 기준의 점수를 설명 없이 합산하지 않는다. |
| 필수 규칙의 완료 판정 | 각 FR과 대응 AC를 확인한다. 접근 통제·동의 분리·충돌 방지 위반을 AI 품질 평균으로 상쇄하지 않는다. |
| AI 품질 완료 판정 | 사전에 확정한 지표별 목표와 허용 보류 범위를 적용한다. 목표값이 미정이면 결과는 보고할 수 있지만 해당 품질 검수를 완료로 표시할 수 없다. |
| 미완료 항목 처리 | 미실행·실패·기준 미정 항목이 남으면 해당 기능 검수를 미완료로 기록한다. |
| 담당자 공동 확인 | 평가 담당자와 기능 담당자가 기능 검수·품질 판정·보류 및 오류 처리·사용 기준 버전을 함께 확인한다. |

근거: [명세서 §8.4 평가 보류·비교 불가 처리 및 완료 판정][spec-metrics].

## 8. 아직 미정이지만 결정 업무로 추가된 항목

명세서 제9장은 실제 담당자를 배정하고 결정 내용·담당자·확정일·버전을 기록하도록 요구한다. 정해진 시점까지 기준을 확정해야 하며, 미정 항목을 구현·검수 완료로 처리하지 않는다. 확정 후 변경하면 관련 요구사항과 시나리오를 갱신하고 다시 확인한다.

아래는 이미 확정된 기능과 구분해야 하는 **결정 과제**다.

## 9. 기능 추가가 아닌 범위·문서 구조의 명시

| 항목 | 명세서에서 추가한 명시 | 근거 |

실결제·커머스·폐기 및 교체 제휴·B2B 연동의 향후 확장 구분과 영상·음성 입력·예방 관리·이사 관리 등의 확장 방향은 원문에도 있다. 이들을 명세서가 새로 추가한 현재 구현 기능으로 분류하지 않는다.

| 관찰 사실·사용자 설명·AI 추정·미확인 구분 | [§5.3][plan-ai] | 정보 성격을 구분하는 원칙은 기존이다. |
| 단계별 공개 통제·별도 활용 동의·비식별화 | [§7.4][plan-information] | 기본 원칙은 기존이다. 단계별 필드·종료 후 권한·목적 간 독립 처리·실패 차단이 구체화됐다. |
| 생성·평가 에이전트 분리와 규칙 기반 검사 | [§7.2][plan-evaluation] | 평가 방식 자체는 기존이다. 목표값·산식·버전·완료 판정 절차가 추가됐다. |
| 평가 보류 집계와 모의평가 한계 | [§7.2][plan-evaluation] | 보류를 기록하고 모의평가를 실제 비용 절감 효과와 구분하는 원칙은 기존이다. |
| 변화 분석 대상 한 가지 유형 | [§6.3][plan-history], [§7.1][plan-scope] | 단일 유형을 중심으로 검증한다는 제한은 원문에 있다. 어떤 유형인지를 정하는 과제가 남아 있다. |

## 11. 확인 시나리오 27개 대조표

시나리오 번호의 신설이 곧 신규 서비스 기능을 뜻하지는 않는다. 아래는 각 AC가 원문 기능을 검수하는지, 추가 정책을 검수하는지 확인하기 위한 연결표다. 상세 기대 결과는 [명세서 제7장][spec-acceptance]을 따른다.

| 시나리오 | 대조 결과 | 이 보고서의 관련 내용 |
| --- | --- | --- |
| AC-01 | 사진 한 장, 문답, 사용자 확인, 정보 성격 구분 등 기존 흐름을 검수한다. | 제10장 |
| AC-02 | 자가 해결 가이드와 해결·미해결 분기, 기존 기록 유지 등 기존 흐름을 검수한다. | 제10장 |
| AC-03 | 기존 AS 안내에 제조사 미확인 시 추가 확인을 포함한다. | 제2장 |
| AC-04 | 실제·모의 사례 구분, 원본 기반 추천, 담당 기사 연결 등 기존 기능을 검수한다. | 제10장 |
| AC-05 | 기존 조건 필터링에 적합 후보가 없을 때 안내하는 처리를 포함한다. | 제2장 |
| AC-06 | 기존 동선 추천에 구체적 추가 이동 시간 순위와 충돌 후보 제외를 적용한다. | 제5장, 제7.1절 |
| AC-07 | 기존 중복 방지에 조회 후 변경된 일정의 재검사를 포함한다. | 제3장 |
| AC-08 | 기존의 할인 미보장·세부 비용 구분을 검수한다. 조건부 비용 표시를 구체화한다. | 제6장, 제10장 |
| AC-09 | 기존 긴급 대응과 AI 판단 한계를 검수한다. | 제10장 |
| AC-10 | 기존 사진 분석에 잘못된 영역·설명·필수 출력 누락의 독립적인 실패 판정을 포함한다. | 제7장 |
| AC-11 | 기존 경과 보강에 날짜 미확인 관리와 수정 요약 재확인을 포함한다. | 제2장, 제6장 |
| AC-12 | 기존 기사 사진 요청·사용자 보완·방문 준비사항 연결을 검수한다. | 제10장 |
| AC-13 | 변경 합의, 취소 후 일정 해제·탐색 복귀, 재상담·재예약, 요청당 활성 예약 제한을 검수한다. | 제3장 |
| AC-14 | 기존 완료 기록·별도 동의 원칙을 검수한다. 자동 공개하지 않는 동작을 명시한다. | 제4장, 제10장 |
| AC-15 | 기존 선택 상대 접근 통제를 요청·사진 접근 차단으로 확인한다. | 제4장 |
| AC-16 | 기존 임대인 공유에 선택 범위와 다른 요청·비공개 상담 제외를 적용한다. | 제4장 |
| AC-17 | 저장·분석 실패의 안내·재시도·입력 보존과 정보 부족 보완을 검수한다. | 제6장 |
| AC-18 | 작업 지역·방문 조건의 단계별 입력과 변경 시 추천·견적 재검사를 검수한다. | 제2장, 제3장 |
| AC-19 | 상세 주소·연락처 누락·지역 불일치 시 예약 차단과 확정 전후 공개 범위를 검수한다. | 제2장, 제4장 |
| AC-20 | 동선 탐색·기사 참여 의사·사용자 선택·기사 수락·견적 순서와 직접 선택 예외를 검수한다. | 제2장 |
| AC-21 | 기존 프로필·일정 관리를 구체적 입력과 조건 판별·동선 반영 기준으로 검수한다. | 제6장 |
| AC-22 | 확정 예약과 충돌하는 일정 변경 차단 및 일정 수정·예약 확정의 동시 처리를 검수한다. | 제3장 |
| AC-23 | 견적 수정·만료·철회·거절·버전 검사와 확정 당시 조건 보존을 검수한다. | 제3장 |
| AC-24 | 복수 상담 분리, 종료·취소·완료 후 권한, 원본 사진 경로 통제를 검수한다. | 제4장 |
| AC-25 | 포트폴리오와 AI 활용 사이의 독립적인 목적별 동의를 검수한다. | 제4장 |
| AC-26 | 비식별화 실패·미완료 시 활용 차단과 평가 자료의 식별 정보 제거 확인을 검수한다. | 제4장, 제7.1절 |
| AC-27 | 기존 요청 기록을 통합 조회하고 취소·종료 후에도 본인 이력이 유지되는지 확인한다. | 제6장 |
